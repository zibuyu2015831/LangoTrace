# 架构开发备忘录

状态：Accepted
创建日期：2026-05-20

本文档定义 `docs/architecture/notes/` 的用途、边界和读取规则。

## 1. 用途

`docs/architecture/notes/` 用于保存尚未进入正式实施方案、正式架构文档、spec 或 ADR 的架构级开发备忘录。

适合放入本目录的内容包括：

- 当前任务为了未来能力预留的架构边界。
- 尚未进入实施阶段的跨模块扩展问题。
- 后续开发某一能力时必须重新检查的风险、约束和候选模型。
- 需要避免后续 AI 会话遗漏的架构提醒。

示例：

- 当前本地持久化任务为未来同步功能留下的对象 ID、软删除、tombstone、device state 和冲突处理提醒。
- AI Provider 任务为未来请求审计、Keychain 迁移或离线队列留下的边界提醒。
- 附件存储任务为未来导出恢复、对象存储和隐私彻底删除留下的约束提醒。

## 2. 非权威边界

本目录不是最终事实源。

- 不替代 `docs/plans/active/` 中的任务方案。
- 不替代 `docs/spec/` 中的开发一致性规范。
- 不替代 `docs/architecture/` 根目录下的正式架构说明。
- 不替代 `docs/decisions/` 中的 ADR。
- 不记录逐步实施计划、任务状态或完成验证结果。

后续任务采纳某份备忘录中的结论后，必须把被采纳内容写入对应任务方案、正式架构文档、spec 或 ADR。仍停留在本目录的内容只能作为设计输入和检查清单，不能直接当作已接受实现要求。

## 3. 创建条件

开发、审查或方案讨论过程中，如果发现以下情况，应主动创建或更新本目录中的备忘录：

- 当前任务明确不实现某个未来能力，但当前设计会影响该未来能力的边界。
- 一个问题横跨数据、同步、AI、权限、导出、附件、付费或三端架构，不能只留在单个任务方案中。
- 讨论形成了重要风险清单或候选方案，但尚未到 ADR 或 spec 的稳定程度。
- 后续功能若忽略该问题，可能造成数据库迁移、同步协议、隐私边界或模块边界返工。
- 相关提醒需要被多个未来任务复用，而不是只服务当前任务收尾。

如果只是单个任务的执行细节、验证记录或用户确认链路，应写入对应 `docs/plans/active/` 或 `docs/plans/done/`，不写入本目录。

## 4. 命名规则

推荐命名：

```text
docs/architecture/notes/YYYY-MM-DD-<topic>-notes.md
```

文件应至少包含：

- 标题。
- 状态。
- 创建日期。
- 适用范围。
- 目的。
- 已有设计留下的扩展点。
- 后续任务必须重新决策的问题。
- 不应在当前阶段提前实现的内容。

状态可使用：

- `Draft`：正在形成，仍需后续确认。
- `Accepted`：作为后续设计输入保留。
- `Superseded`：已被正式架构文档、spec、ADR 或任务方案取代。
- `Archived`：仅保留历史参考，不再作为后续设计输入。

## 5. 读取规则

创建或更新涉及数据、同步、AI Provider、权限、附件、导出、StoreKit、三端架构或长期记忆的任务方案前，应检查本目录是否存在相关备忘录。

读取后必须在任务方案中说明：

- 是否存在相关备忘录。
- 采纳了哪些提醒。
- 哪些提醒暂不采纳，以及原因。
- 是否需要把备忘录中的内容提升为 spec、正式架构文档或 ADR。
