# 设置状态投影开发备忘录

状态：Accepted
创建日期：2026-05-24
适用范围：设置主列表、能力详情、AI Provider、同步、导入导出、本地数据和隐私边界状态展示。

## 1. 目的

当前 `SettingsCapability.status` 仍带有早期 UI 设计阶段的开发进度含义，用于临时标注哪些页面已可交互、哪些仍是本地预览或未接入。该字段不应继续直接驱动面向用户的设置主列表角标。

本备忘录记录后续扩展设置状态基础设施时必须重新设计的边界，避免把开发完成度、产品原则和真实用户配置状态混成一个模型。

## 2. 已有设计留下的扩展点

- `CapabilityStatus` 当前只有 `ready`、`mockOnly` 和 `unavailable`，粒度不足以表达真实设置健康状态。
- `CapabilityStatusBadge` 仍适合结果面板、详情页和状态解释组件，但设置主列表应单独决定是否显示状态。
- AI Provider、同步、导入导出、权限和本地数据后续都需要真实投影：是否已配置、是否启用、是否缺密钥、是否需重测、是否最近失败、是否只本地可用。
- 设置主列表的状态应是用户行动提示，不是开发排期提示。

## 3. 后续任务必须重新决策的问题

- 是否新增 `SettingsCapabilityListStatus` 或 `SettingsCapabilityProjection`，把列表当前值、详情页状态、开发完成度拆开。
- AI Provider 列表状态是否读取非敏感 profile projection，例如 Provider 名称、缺密钥、需重测、部分可用。
- 同步列表状态是否表达 `未启用`、`iCloud 已启用`、`对象存储待验证`、`冲突需处理`。
- 导入导出、本地数据和隐私边界是否需要真实可操作状态，还是只保留说明型设置入口。
- macOS Settings scene 是否需要比 iPhone 设置主列表更高密度的 trailing current value。

## 4. 不应在当前阶段提前实现的内容

- 不为了隐藏当前角标而立即扩展数据库 schema。
- 不把开发完成度写入用户可见字符串或可访问性标签。
- 不在设置主列表渲染路径读取 Keychain 明文或执行网络探测。
- 不把 `本地优先` 作为某个 row 的状态字段；它属于产品和隐私边界。
