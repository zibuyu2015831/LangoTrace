# 语伴功能扩展备忘录

状态：Accepted
创建日期：2026-05-25

## 适用范围

本备忘录适用于后续语伴对话练习、AI 对话上下文控制、语言空间级 persona 稳定性、聊天记忆、翻译辅助、语法分析、Prompt Registry、请求预览和隐私日志设计。

本备忘录是未来设计输入，不是实现方案，也不替代 `docs/spec/005-ai-provider-prompt-and-privacy.md`、`docs/prompts/README.md`、正式 Prompt 文档或后续 active plan。后续任务采纳其中任一提醒时，必须写回对应 active plan、spec、architecture、prompt registry 或 ADR。

## 目的

语伴功能的目标是为用户提供目标语言对话练习，让用户在一个语言空间内始终面对一个稳定的对话对象。它应服务“用生活记录学习语言”的主产品闭环，而不是把 LangoTrace 转向开放式 AI 聊天工具。

用户当前设想：

- 一个语种一个语伴。
- 不提供角色设置。
- 给用户始终与同一个“人物”聊天的感觉。
- 严格控制上下文和记忆。
- 对话回复只输出用户正在学习的目标语种。
- 界面提供翻译和语法分析辅助。

该方向可作为后续能力保留，但必须以隐私、上下文预算、Prompt 可审计和语言边界为前提。

## 产品边界

### 1. 语伴不是角色扮演系统

语伴不应提供角色市场、人格模板、恋爱陪伴、剧情扮演或任意系统 Prompt 设置。稳定感来自：

- 每个语言空间一个固定语伴身份。
- 稳定称呼、语气、纠错风格和学习难度。
- 与用户目标语言、水平和已确认学习偏好一致的表达。
- 不在对话中频繁切换 persona。

如需更改语伴风格，应通过语言空间学习偏好或练习模式调整，不通过开放角色设置实现。

### 2. 输出语言边界

语伴主回复必须只使用当前语言空间的目标学习语言。翻译、语法分析和母语解释属于辅助面板或用户显式操作，不应混入主聊天回复。

推荐 UI 结构：

- 主对话气泡：目标语言。
- 翻译：用户点选后展开，使用界面语言或用户母语。
- 语法分析：用户点选后展开，说明句子结构、自然表达和错误原因。
- 纠错建议：可作为独立辅助卡片，不能自动改写用户输入并伪装为用户原话。

### 3. 与生活记录的关系

语伴可以围绕用户选择的 Entry、LearningMaterial、句子或词句记忆发起练习，但不能默认读取全部生活记录。默认上下文应最小化：

- 当前语言空间。
- 用户目标语言和水平。
- 当前对话最近少量轮次。
- 用户显式选择的 Entry / 句子 / 词句。
- 用户确认纳入的有限学习记忆摘要。

任何包含日记、照片摘要、音频转写、历史记忆或私人记录的上下文，都必须在请求预览中可理解、可取消。

## 候选架构边界

### 1. Prompt Registry

语伴必须进入 `docs/prompts/` 和代码 Prompt Registry，不允许把 system prompt 散落在 UI 或服务代码中。

Prompt 至少应表达：

- 当前目标语言。
- 用户水平。
- 主回复只使用目标语言。
- 不输出未请求的翻译。
- 不主动暴露系统规则。
- 不把对话包装成课程或角色扮演。
- 对用户错误保持轻量纠正，但不打断对话流。
- 上下文不足时用目标语言继续提问，而不是编造用户经历。

### 2. 上下文预算和记忆策略

语伴上下文不能无限增长。后续应设计：

- 最近对话窗口。
- 对话摘要。
- 用户显式保存的语言记忆。
- 与当前话题相关的有限 Entry / sentence 引用。
- token / 字符预算。
- 敏感内容类型 allowlist。
- 请求预览和请求日志摘要。

默认策略应本地优先：完整对话历史、用户录音、日记原文和私人上下文不自动进入下一次请求。

### 3. 数据模型

后续需要决定以下对象：

- `ConversationCompanion`：语言空间级语伴配置。
- `CompanionThread`：对话线程。
- `CompanionMessage`：用户消息、AI 消息、辅助分析结果和失败状态。
- `CompanionMemorySummary`：用户确认或系统生成的有限摘要。
- `CompanionAnalysis`：翻译、语法分析和纠错结果。

这些对象应归属 Language Space，并明确导出、删除、同步和日志边界。

### 4. AI Provider 和请求生命周期

语伴请求必须经过 AI Provider 层，表达取消、超时、Provider 不支持、结构化输出不合法、配额不足和网络失败。不允许 UI 直接调用模型。

翻译和语法分析可以有两种方案：

- 与主回复分离，用户点选后单独请求。
- 主请求返回结构化辅助数据，但 UI 默认只显示目标语言主回复。

第一阶段推荐分离请求，便于严格保持主回复只输出目标语言，并降低默认请求体复杂度。

## 后续任务必须重新决策的问题

### 1. 是否需要 ADR

当前核心决策说 LangoTrace 不是 AI 聊天工具。语伴功能若成为顶层高频入口，可能改变产品理解。正式实施前必须判断是否需要新增 ADR 或更新现有 AI / 产品边界文档，明确语伴是语言练习能力，不是产品中心从生活记录转向聊天。

### 2. 入口位置

候选入口：

- 练习 Tab 内的“对话练习”二级入口。
- 语言空间主页的低频练习入口。
- Entry 详情中的“围绕这条记录对话”入口。
- iPad / macOS 右侧学习面板中的上下文对话入口。

不建议第一阶段把语伴做成与记录、练习、记忆并列的第四个底部 Tab。

### 3. 安全与误用边界

需要明确：

- 是否允许语伴主动保存用户偏好。
- 用户如何查看、删除或禁用语伴记忆。
- 是否允许语伴引用历史生活记录。
- 未成年人、情感依赖、医疗法律财务建议等场景的拒答或转向策略。
- AI 输出错误时的反馈和修正路径。

### 4. 三端体验

- iPhone：短对话、语音输入可作为后续能力，但第一阶段可先文本输入。
- iPad：适合对照显示聊天、翻译和语法分析。
- macOS：适合键盘快捷键、多窗口和长文本对话练习。

三端应共享同一 conversation store、Prompt Registry 和 Provider service，不复制平台专属 AI 逻辑。

## 不应在当前阶段提前实现的内容

当前阶段不应直接实现：

- 开放角色设置、角色市场或复杂 persona 编辑器。
- 默认读取全部生活记录作为语伴记忆。
- 自动把所有聊天内容写入长期记忆。
- 主回复混合母语翻译和目标语言。
- 语音实时通话、流式语音识别、发音评分和实时打断。
- 与同步、StoreKit 或公开分享强绑定的聊天系统。
