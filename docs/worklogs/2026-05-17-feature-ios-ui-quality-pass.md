## 1. 背景

当前 App Shell 已经从工程占位推进到可浏览的产品骨架，包含欢迎页、首次语言空间引导、iPhone Tab、iPad 学习桌面和 macOS 工作台。用户在 iPhone 17 Simulator 中查看后反馈：页面出现过非全屏显示问题，同时希望从专业 iOS UI 交互设计师角度，对当前页面实现进行全面审查和优化。

本次工作属于 UI 质量提升，不应提前接入数据库、真实 onboarding、AI、同步或语音能力。目标是在 Stage 0 / Stage 1 之间，把现有静态骨架调整到更接近付费 iOS App 的首版质感和交互基础。

## 2. 目标

本次完成后，应达到以下可验证结果：

- iPhone 启动和首次引导页面占满屏幕，不出现黑色 letterbox、内层孤立大卡片或不自然内部滚动边界。
- 欢迎页、首次引导页和 iPhone 主体页使用统一的 iOS 视觉语言：温润纸感背景、清晰层级、克制深松石强调色、低饱和金色点缀。
- 首次引导页更像原生 iOS onboarding：核心问题清晰、表单负担低、底部主按钮稳定可达，并兼顾 Dynamic Type。
- iPhone 主体页更像真实产品首版，而不是功能列表：顶部有语言空间上下文，今日页聚焦“记录一点生活”，练习和记忆入口层级清晰。
- Tab 和设置入口保持简洁：一级 Tab 仍为 `今日 / 记录 / 练习 / 记忆 / 设置`，不引入“我的”或 Project 概念。
- 关键触控目标满足 iOS 基本可达尺寸，图标按钮有 accessibility label。
- 页面中 Mock 状态不误导用户认为 AI、同步、数据库或 TTS 已真实实现。
- 不破坏 iPad 和 macOS 当前骨架；如调整设计 token，应保持跨端一致。
- iPhone 首屏必须突出产品北极星 `用生活记录学习语言。`，避免优化成普通日记 App、翻译 App、课程 App 或 AI 聊天入口。
- 语言空间必须作为当前学习上下文稳定可见，并为未来多语言空间切换保留入口，但不能把多语言管理做成首次使用负担。
- 今日页应提前露出长期记忆的产品感：最近记录、待练句子、词句记忆和相似生活片段之间要有自然连接。
- 隐私和本地优先应以低干扰状态表达建立信任，不做成吓人的权限/设置页面。

## 3. 范围

本次会处理：

- 审查并优化 `WelcomeView`、`OnboardingView`、`PhoneMainView` 和共享 design token。
- 修正 iPhone 首次引导页的版式：去除桌面式大表单感，优化顶部分组、输入控件、水平自评和底部 CTA。
- 优化 iPhone 主体页的页面框架：增加更自然的语言空间上下文、状态 badge、主要记录入口和列表层级。
- 适度补充可复用 UI 小组件，例如状态徽章、语言空间胶囊、主要行动按钮、内容分组。
- 补充 iPhone 信息架构中的产品锚点：
  - 当前语言空间。
  - 本地优先 / 未配置 AI。
  - 今天记录一点生活。
  - 最近生活记录。
  - 下一步练习。
  - 个人语言记忆。
- 保持当前 launch screen 修复方案，并纳入最终验证。
- 更新本 worklog 的实施记录和验证结果。

## 4. 不做什么

本次不处理：

- SQLite / GRDB 持久化。
- 真实语言空间创建保存。
- 真实 AI Provider、Keychain、TTS、Speech、OCR、相机或照片权限。
- 真实同步、对象存储、iCloud、StoreKit。
- iPad 和 macOS 的完整产品级重设计。
- 深色模式完整适配。
- App icon 最终品牌定稿。
- 完整多语言本地化。
- 真实语言空间切换菜单。
- 真实目标语言写作检测流程。
- 真实手写文章拍照录入流程。
- 真实向量检索和相似记忆召回。

## 5. 分析

### 5.1 当前主要 UI 问题

1. 首次引导页信息密度偏桌面化。当前把三组 Picker 放进一个大面板，再加一个底部按钮和文本摘要，结构可用但不够像高质感 iOS 首次体验。
2. 滚动区域和安全区关系需要更原生。iPhone onboarding 应允许小屏滚动，但不能让用户感觉是在屏幕中间滚动一张大卡片。
3. 当前视觉 token 初版可用，但组件层级还少。面板、chip、badge、按钮和列表都用了相近样式，缺少主次差异。
4. 今日页仍像功能占位页。`今天记录一点生活` 是正确方向，但首屏需要更明确的主行动、语言空间上下文和“本地优先 / 未配置 AI”的低干扰状态。
5. 设置和隐私表达方向正确，但应避免在主流程中过早抢占注意力。
6. 现有文本较多，移动端需要更多短句、分组和留白，减少“说明书感”。

### 5.2 产品交互判断

语迹的 iPhone 首屏应服务高频轻量行为：随手记录、拍照引导、听一句、跟读一句。它不是功能目录，也不是营销封面。付费感不来自复杂装饰，而来自：

- 状态清楚。
- 主行动明确。
- 文案少而准。
- 控件像原生 App。
- 视觉克制但有品牌记忆点。

### 5.3 可扩展边界

本次 UI 应为后续真实功能预留位置：

- 欢迎页未来承载本地数据加载、加密检查、最近语言空间恢复。
- 首次引导未来可插入“是否现在配置 AI Provider”，但不作为当前门槛。
- 今日页未来接入记录输入、拍照、录音和最近练习。
- 语言空间上下文未来可变成切换菜单。
- 设置页未来承载 Provider、同步、隐私、购买恢复。

### 5.4 与产品愿景的再校准

本次优化不能只理解为“让页面更好看”。语迹的核心差异是“把用户自己的生活变成语言学习材料”，因此 iPhone 首屏应始终围绕真实生活记录展开。

应避免的偏移：

- 过度强调 AI 生成，导致产品像 AI 翻译工具。
- 过度强调练习入口，导致产品像课程或刷题 App。
- 过度强调词句收藏，导致产品像传统背单词 App。
- 过度强调隐私配置，导致首次体验像高级设置页。
- 过度强调 App 名称和 slogan，导致欢迎页像营销页。

更合理的心智路径是：

```text
我今天有一点生活想记录
-> App 帮我变成目标语言
-> 我可以听、读、练、收藏
-> 这些内容慢慢成为我的语言记忆
```

### 5.5 首次体验边界

首次启动只应收集创建第一个语言空间所需的最小信息：母语、目标语言、水平自评。AI Provider、同步、目录选择、词典导入和高级 prompt 都应延后。

但首次体验也需要给用户一个清晰预期：

- 数据默认保存在本机。
- 未配置 AI 时不会发送内容。
- 后续可添加新的学习语言。
- 当前创建的是一个目标语言的长期档案，而不是账号、Project 或课程。

这些信息应轻量出现，不能形成新的决策负担。

### 5.6 长期记忆的 UI 伏笔

即使本次不实现向量索引，也应在 Mock 信息架构中提前体现长期记忆系统，避免后续页面只剩记录和练习两个短期动作。

建议在 iPhone 主体页中保留以下“伏笔”：

- 今日页显示最近一条生活记录以及可继续练习的句子。
- 记忆页不仅显示单词，还显示短语、整句、相似生活片段和错误模式。
- 练习页的入口与真实记录关联，而不是孤立练习项目。
- 状态文案中使用“个人语言记忆”“相似生活片段”“本地可重建”等概念，但保持用户可理解。

### 5.7 多语言空间扩展

当前示例使用 `中文 -> 英语 · B1` 是正确的，但 UI 不能写死“英语学习 App”心智。

本次实现中允许使用英语示例内容，但组件和文案应保持多语种可扩展：

- 文案使用“目标语言”或当前空间的语言名，而不是把英语写成产品默认唯一目标。
- 语言空间胶囊未来应能打开切换菜单。
- 记录、练习、记忆的 Mock 数据可以是英语，但结构必须能承载日语、法语等语言。
- 不把英语专属能力作为底层组件命名，例如避免把通用组件命名成 `EnglishPracticeCard`。

### 5.8 隐私信任与权限边界

语迹处理日记、照片、音频和 AI 请求，用户信任感是付费价值的一部分。本次 UI 应提前建立“用户掌控”的感受，但不把隐私说明做成大段说明。

推荐表达方式：

- 使用简短状态：`本地优先`、`未配置 AI`、`默认不发送`。
- 对照片、AI 和同步相关入口使用未来可扩展的请求预览语义。
- 设置页保留“AI Provider”“对象存储”“本地优先”的 mock 分组。
- 不在首次引导中要求权限，也不展示相机、麦克风、照片权限弹窗。

### 5.9 iOS 交互边界

本次需要补充以下 iOS 体验检查：

- 小屏设备上底部 CTA 不能被 Home Indicator 或 Tab Bar 遮挡。
- Dynamic Type 放大时，水平自评控件不能导致不可操作；必要时后续改为列表选择。
- 横屏不作为首要设计目标，但不能出现内容完全不可达。
- `ScrollView` 只用于内容溢出，不制造页面中间的孤立滚动卡片。
- 可点击卡片必须有明确按钮或 affordance，不能只依赖用户猜测整卡可点。

## 6. 方案

推荐采用“iPhone 优先质量打磨，跨端 token 稳定”的方案。

### 6.1 设计策略

- 保留温润纸感背景，但减少大面积封闭卡片。
- 引导页使用更明确的 onboarding 层级：品牌/进度感、问题标题、短解释、三个输入分组、底部固定 CTA。
- Picker 保持原生控件，不自造复杂下拉，避免当前阶段过早做定制交互。
- 水平自评使用 segmented control，但增加上下文说明，让 A1-C2 对新用户更容易理解。
- 主按钮使用深松石色，按钮文案保持动作导向。
- 状态信息使用轻量 badge，不与主 CTA 抢层级。
- 欢迎页不承担功能介绍，只承担品牌确认、加载过渡和状态分流。
- 引导页不引入 AI、同步、目录、词典和 Prompt 选择，避免首次体验过载。
- 页面中的“高级感”主要来自留白、层级、触控舒适度和文案克制，而不是阴影、渐变或装饰图形。

### 6.2 iPhone 主体页优化

- `PhonePage` 顶部增加当前语言空间胶囊和本地状态，而不是只放 subtitle 文本。
- 今日页首屏结构调整为：
  - 当前空间：`中文 -> 英语 · B1`
  - 主行动：`今天记录一点生活`
  - 快捷入口：写一句、拍照、听一句
  - 最近记录：雨天咖啡馆
  - 下一步练习：跟读 / 听写 / 回译
- 记忆页结构调整为：
  - 收藏词句。
  - 整句表达。
  - 相似生活片段。
  - 常见错误模式占位。
- 记录、练习、记忆、设置页保持 mock 骨架，但用更像列表和分组的布局，降低卡片堆叠感。

### 6.3 未来功能预留

本次 UI 不实现以下能力，但应在命名、组件和布局上不阻碍后续扩展：

- 目标语言自主写作检测与修改。
- 拍照录入手写文章。
- Prompt Preset 选择与自定义。
- 语言空间切换和添加学习语言。
- 请求预览与“即将发送 / 不会发送”说明。
- 本地向量索引和相似记忆召回。

### 6.4 替代方案

- 方案 A：只修 onboarding。成本最低，但主体页仍会显得像占位功能列表。
- 方案 B：做完整 iPhone 重设计并同步重做 iPad/macOS。质量最高，但范围过大，会偏离当前阶段。
- 方案 C：iPhone 优先优化，保留 iPad/macOS 骨架，只调整共享 token 和可复用组件。推荐采用。

推荐方案 C。它最符合当前阶段：先让 iPhone 体验能代表产品气质，同时不提前引入真实业务复杂度。

## 7. 风险与边界

- 风险：为了高级感过度弱化边框和文字，导致可读性不足。
  - 缓解：保持文字对比度，关键状态不只靠颜色。
- 风险：底部固定 CTA 与小屏键盘、横屏或 Dynamic Type 冲突。
  - 缓解：使用 safe area inset 或滚动内容底部预留空间，并在模拟器验证。
- 风险：新组件过多导致早期设计系统过度抽象。
  - 缓解：只提取当前重复且稳定的组件，不建立完整组件库。
- 风险：Mock UI 过真，误导功能完成度。
  - 缓解：保留 `未配置 AI`、`本地演示`、`默认不发送` 等状态文案。
- 风险：视觉优化后产品心智变成普通日记。
  - 缓解：首页必须出现目标语言学习动作和下一步练习，不只展示记录。
- 风险：视觉优化后产品心智变成普通翻译工具。
  - 缓解：保留练习、记忆、相似片段和错误模式，不只展示双语文本。
- 风险：英语示例让产品显得只支持英语。
  - 缓解：组件命名和通用文案保持多语种，中英文示例仅作为当前 mock 内容。
- 风险：首次引导过度解释本地优先和 AI 配置。
  - 缓解：只给最小信任提示，高级配置放到设置。
