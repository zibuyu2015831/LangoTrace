## 1. 一句话定位

> 学习者模型是语迹内部一个**本地优先、持续演进、系统级（跨语言空间）**的子系统，统一承载「App 对用户的、不断积累的理解」，分三层：**Ability（能力画像：各语言的水平、知识覆盖、常犯错误，按语言维护）**、**Memory（记忆：生活事实、学习目标、对话情景）**、**Style（表达与认知印记：写作风格 + 观察角度 / 思维方式 / 思维习惯）**。它从用户的真实记录、对话、练习中派生，并作为**唯一可信的用户上下文来源**，喂给材料生成、解释模式、改写 / 写作、练习、复习、进步可见与「语伴」。（三层定义详见 §13；下文 §2 的「两平级子域」为旧表述。）

它对应智能辅导系统（ITS）经典三元组中的 **Learner Model**（另两个是领域模型、教学模型）。

---

## 2. 关键定位：平级子域，而非父子从属

最初的设想是「水平评测是关系记忆模块的一部分」。本文件**纠正这一从属关系**：

- **关系记忆**（记得你养了猫、在学吉他）本质偏 **语伴专属**、服务对话连续性。
- **水平评测**是**横向能力**，服务全 App（材料生成、解释模式、练习、复习、进步可见），不依赖语伴。

若让横向的水平评测从属于偏垂直的关系记忆，会把全局能力塞进一个功能特性之下，造成依赖与语义错位（材料生成要用水平信号却要穿过「关系记忆」）。

**正确抽象**：两者都是「App 对用户的理解」，即 Learner Model 的**两个平级子域**：

- **A. 能力画像（Proficiency Profile）** —— 横向，广泛消费。详见 [`02-dynamic-proficiency-assessment.md`](02-dynamic-proficiency-assessment.md)。
- **B. 关系记忆（Relationship Memory）** —— 初期由语伴驱动，可复用。源自 [`03-conversation-partner.md`](03-conversation-partner.md) §3.11。

## 3. 必要性

**判断准则：当「关于用户的派生知识」存储 ≥ 2 个、且治理姿态相同时，抽出公共模块开始划算。**

两个子域高度共享：

- **同源证据**：都吃 记录 / 语伴对话 / 练习 / 记忆候选 同一批信号。
- **同一隐私存储姿态**：高敏感、本地优先、默认不同步、派生可重建、可查看、可删除、按语言空间隔离。
- **同一批消费者**：语伴（人设上下文 + 难度）、材料生成、练习、水平总览页。
- **同一治理窗口**：用户「查看 / 导出 / 删除 App 对我的了解」应是**一个**统一入口，而非散在多处。

不抽模块的代价：两个子域各自重造「读取用户数据 → 派生 → 存储 → 隐私边界 → 展示 → 删除 → 按空间隔离」，消费者要分别接多个 store，隐私边界还可能不一致。

对一个**本地优先、隐私是北极星**的产品，「有一个可审计的、唯一的『我们了解你什么、存在哪、怎么删』的地方」本身就是**隐私卖点**（可呼应动态水平评估 §7.2 的智能性叙事）。

> 必要性结论：**中高，且随子域增多而上升**。只有能力画像一个子域时，模块是过度设计；关系记忆的加入正是「该抽模块」的临界点。

---

## 4. 可行性

- **架构上可行**：它是叠在现有证据（记录、`memory_candidates` 已在 GRDB）之上的**增量子系统**，不需推翻现有模块；新增 Core 模型 + GRDB 表 + 服务 / Provider seam。
- **时序张力（必须正视）**：
  - 能力画像建议**先于**语伴做（语伴依赖它）。
  - 关系记忆**随 / 后于**语伴做（它是语伴对话连续性特性）。
  - 两者同属一个模块 → 模块无法「先于语伴整体完成」。
- **缓解（先立边界、增量填充）**：依 `CLAUDE.md` 1.2「首版可限功能范围，但底层边界要预留」——**现在就先把模块边界 / 存储命名空间 / 查询 API 立起来，先只填充「能力画像」子域**；关系记忆等语伴落地时填进同一边界，无需重写。

## 5. 实现形态

### 5.1 模块与子域
**模块：`学习者模型 / Learner Model`（按语言空间维护）**

- **A. 能力画像 `ProficiencyProfile`**：CEFR 估计 + 置信度、分技能（理解 vs 产出）、知识覆盖、错误模式、趋势、来源标记。（细节见动态水平评估构想）
- **B. 关系记忆 `RelationshipMemory`**：用户生活 / 偏好 / 目标的语义事实集合，例如 `{ kind: 生活事实 / 偏好 / 目标 / 人际, text, salience 显著度, source, lastSeen, confidence, scope }`。
- **(待议) C. 掌握状态**：`memory_candidates` 的「已掌握 / 待巩固」状态有两栖性（见 §6）。

### 5.2 模块提供的公共基础设施
- **证据摄入层**：统一事件 / 观察者接口，被 记录保存 / 分析完成 / 练习完成 / 语伴每轮 喂入。
- **存储**：GRDB 表（`learner_proficiency`、`learner_memory_facts`、评估历史），local-only、排除同步、可重建、按空间外键、随空间级联删除。
- **查询 API `LearnerContextProvider`**：消费者问「现在该知道关于这个用户的什么」（难度信号 + 相关个人事实），语伴 / 材料生成 / 总览页都查它，而非各接多个 store。
- **唯一治理点**：水平总览 / 学习画像页（动态水平评估 §7.1）是本模块的「窗口」；并在此**集中执行**决策 #10 / 本地优先——所有「哪些个人数据可进 prompt」一处把关。

### 5.3 关系记忆专有逻辑
- 对话 → 候选事实抽取、去重合并、显著度衰减、用户可编辑 / 删除、「忘掉这条」。
- **`scope / visibility` 标记**：区分「全局可用」与「仅语伴可用」，避免材料生成莫名其妙用到「你猫的名字」这类只对对话有意义的事实。

## 6. 与 `memory_candidates` / plan 10/11（记忆库）的边界

防止与「记忆库」打架，须划清：

- **`memory_candidates` / SRS 复习队列 = 「要学什么」（领域 + 调度）**，**不**并入学习者模型；
- 但它是能力画像的**关键证据来源**（难度分布、错误模式），学习者模型**读它**；
- **两栖点**：item 的「已掌握 vs 待巩固」**状态**属学习者模型（「你会什么」），**调度机制**属 SRS；建议两者通过 item id 关联，归属在正式拆方案时定清。

## 7. 与核心决策的关系（实施前必须处理）

1. **架构级判断 → architecture note，定边界则需 ADR**：新增子系统、统一用户上下文来源，建议先落 `docs/architecture/notes/`；确定立模块边界后升格 `docs/architecture/` + ADR。
2. **细化决策 #6**：能力画像把「水平」从一次性静态值变为持续演进值（见动态水平评估 §8.1）；本模块是其载体。
3. **本地优先（#11 / ADR-005）/ 派生不同步（#12 精神）**：学习者模型是可重建派生数据，默认 local-only、默认不同步，但聚合高敏感语料，必须经 Repository 边界、可查看、可删除。
4. **隐私 #10 集中把关**：本模块是「哪些个人数据进 prompt」的唯一执行点；任何外发（AI 校准 / 关系记忆抽取）走 Provider 抽象 + plan 09 预览 / 日志 + 显式同意 + 最小发送。
5. **泄露集中点风险**：集中存「关于你的一切」既是治理优势也是单点风险，必须配套统一查看 / 删除 /（默认不）导出。

## 12. 架构师评审（2026-06-13，基于代码与既有文档实地核对）

> 本节是站在系统架构师角度对 §1–§11 的压力测试，基于对 `Packages/*` 代码、`docs/architecture/notes/`、`docs/plans/active/`（2026-06-11 十五本系列）的实地核对追加。仍属 idea 层评审，不替代 ADR / spec / plan；跨文件结论见 [`README.md`](README.md) §6。

### 12.1 总体判断
抽象方向（Learner Model 为上位、能力画像与关系记忆为平级子域）**成立**。但「现在就立统一模块边界 **+** `LearnerContextProvider` 查询 API」存在过度抽象风险，应**拆分采纳**，而非整体一次落地。

### 12.2 关键修正：把「立边界」拆成两半，YAGNI 掉查询 API 的关系记忆半边
- **现在就该做（便宜且正确）**：存储命名空间、按空间外键 + 级联删除、`localOnly` / `excludedFromSync` 策略（沿用 `media_artifacts` 既有 `sync_policy` / `backup_policy` / `export_policy` 三列约定）、以及「唯一隐私治理点」这一概念。这些是 `CLAUDE.md` 1.2 意义上的地基，预留成本低、后续返工代价高。
- **现在不该做（投机性通用化）**：`LearnerContextProvider` 返回「难度信号 ∪ 相关个人事实」的**联合**查询 API。关系记忆尚不存在、唯一真实消费者只有材料生成（且只要难度信号）时，按「一个真实 + 一个想象」的消费者设计联合接口，正是 `CLAUDE.md` 1.1 警告的「临时代码变长期架构」。**建议**：v1 的 provider 只暴露难度 / 覆盖信号；关系记忆随语伴落地时再扩展接口——届时有两个真实消费者，接口才有依据。

### 12.3 掌握状态（§6 / §11 两栖点）建议定论：归记忆系统，Learner Model 只读投影
mastery「状态」本质就是 SRS 调度器的计算产物（interval / ease / last-reviewed），与「调度机制」不可分割。把状态切给 Learner Model、调度留给 SRS，会制造跨两个 store 的一致性同步问题且**零收益**。**建议**：掌握状态留在 plan 10 / 11 记忆系统；Learner Model 把「覆盖率 / 已掌握比例」当作**只读派生视图**聚合，不持有状态真值。这样「你会什么」只是 SRS 状态 + candidate kind 的投影，两栖点自然消解。

### 12.4 单点集中的隐私分级 —— 一个 ADR 级新问题（文档未覆盖）
关系记忆是全 App 最浓缩的 PII（「养了猫、在学吉他、目标移民」）：它从日记**蒸馏**、被**索引**、可**查询**，敏感度甚至高于来源日记本身。决策 #9 只要求**凭证级**进 Keychain，未对这类「派生但高浓缩」的事实表态。**待用户决策**：关系记忆是否需要超出默认 SQLite 文件的静态加密（如 SQLCipher 或字段级加密），还是依赖 App 私有容器 + `FileProtection` 即可？此问题应在升格 ADR 时正面回答，不应默认「与普通派生缓存同级处理」。

### 12.5 与既有 2026-05-25 语伴备忘录的归并（重要）
关系记忆的归属与既有架构备忘录 `docs/architecture/notes/2026-05-25-language-companion-extension-notes.md`（Accepted）**未对齐**：该备忘录把对话记忆定义为**语伴作用域**的 `CompanionMemorySummary`，而本构想要把它升格为**跨 App** 的 Learner Model 子域 `RelationshipMemory`。两者必须二选一或明确分层。**建议折中**：关系记忆**物理上**存于 Learner Model 统一边界（满足统一治理 / 删除 / 导出），但默认 `visibility = companionOnly`，仅在用户或证据明确支持时才提升为全局可见——既保住统一治理，又满足备忘录强调的「默认上下文最小化」。

### 12.6 新增待决点
- v1 是否仅落地存储命名空间 + 隐私治理点，而**推迟** `LearnerContextProvider` 的关系记忆联合接口（§12.2）？
- 关系记忆的静态加密等级（§12.4）。
- 掌握状态归属是否采纳「留在记忆系统、Learner Model 只读投影」（§12.3）。

## 13. 第 3 轮迭代（2026-06-14，用户定稿方向）：三层模型 + 系统级跨空间 + Style + 隐私重定义

> 本轮把 §1–§12 的「两平级子域（能力画像 + 关系记忆）、按语言空间维护」重构为 **Style / Memory / Ability 三层 + 系统级（跨语言空间）** 模型，并定稿 Style 定义、隐私重定义与若干跨层纪律。前文保留为讨论轨迹，**与本节冲突处以本节为准**。仍属 idea 层，升格 architecture 正文 / ADR 须走用户确认链路。

### 13.1 三层模型（取代两平级子域）

| 层 | 是什么 | 分区键 | 主证据 | v1 落地 |
| --- | --- | --- | --- | --- |
| **Ability** | 语言 X 的水平 / 知识覆盖 / 常犯错误 | **按 language code**（同语言多空间共享一份，见 §13.2） | 用户行为 / 产出（AI 生成物禁用，见 02 §4） | 纯本地启发式 |
| **Memory** | 生活事实 / 学习目标 + 对话情景 | **系统级**（事实 / 目标）+ **per-space**（对话情景） | 记录 / 对话（显式记住优先，自动抽取 v2） | 显式记住先行 |
| **Style** | 表达 + 认知印记：写作风格 + 观察角度 / 思维方式 / 思维习惯 | **系统级跨空间** | 源语言产出为主（目标语打折，见 §13.4） | 表面写作风格 = 本地；认知风格 = AI 校准、后置 opt-in |

- 区分口诀：**Style = 模式 / 倾向，Memory = 事实 / 事件，Ability = 能力 / 水平。**
- 三层是 Learner Model 的**内部分解**，与 §1 的 ITS 三元组（learner / domain / teaching）正交。
- 「学习目标」二分：生活动机（如移民）归 Memory；语言水平目标（如英语到 B2）归 Ability。

### 13.2 分区键按层而定 + 全局共享（取代「统一按空间外键」）

- Learner Model 是**系统级、横切所有语言空间**的子系统，不归属任何单一空间（需补充决策 #4：空间是核心信息模型，但 Learner Model 横切空间）。
- Style 与 Memory（生活事实 / 目标）**全局共享**；新建语言空间即复用——冷启动红利（「它本来就认识你」）。
- **不提供单空间「干净重来」opt-out（2026-06-14 用户定）**：共享是全局 / App 级。记录取舍：放弃「为某空间隔离敏感语境」的能力，用户已接受；若未来出现「敏感空间隔离」诉求再议（见 §13.9）。
- 对话情景记忆仍 per-space（属那条对话）。
- **Ability 按 language code keyed，不按空间 id（2026-06-14 定稿）**。依据既有决策:产品**不鼓励**同一学习语言建多个空间，但**底层基础设施明确允许**(`spec/002-navigation-and-routing.md` §「重复目标语言允许创建，不能在 Data 层禁止」;`plans/done/2026-05-20-feature-language-space-data-infrastructure.md` 第 14/26/27/116 行;`target_language_code` 无唯一约束)。同语言多空间(如「英语-工作」「英语-旅行」)若按空间 id 存会把**同一门语言的水平/错误分裂成多份**、证据稀薄且互不相通——这与 Memory/Style 解决过的割裂同型。故 Ability 住系统级 LM、按语言聚合**一份**:
  - **内部二分**:**水平 band / 分技能 / 常犯错误 / 语法盲点 = 按语言**(同语言多空间共享,因这些是语言级事实);**词汇 / 知识「覆盖」= 按语言 + 标签 / 场景切片**(工作 vs 旅行词汇是 domain 差异,而 domain 归**标签 / 场景**而非空间——呼应决策 #5「工作 / 旅行是标签而非空间」)。
  - **不跨语言**:英语 ≠ 日语,各一份;Ability **不**像 Style/Memory 做 App 级语言无关。
  - **默认 1:1(一语言一空间)** 下「按语言」≈「按空间」,与「Ability 跟空间走」的直觉等价;仅在底层允许的同语言多空间场景下显出「不分裂」的正确性。

### 13.3 删除语义三件套（取代「随空间级联删除」）

跨空间后旧的「随空间级联删除」不再适用：

1. **删语言空间** → 删该空间 per-space 对话情景；**保留**系统级 Style / Memory。**Ability 不随空间级联删**:Ability 按语言聚合(§13.2),其证据是空间本地的——删一个英语空间 → 该语言 Ability **从剩余英语空间证据重算**(不整体消失);删掉该语言**最后一个**空间 → 证据归零 → 该语言 Ability 按 provenance 整体撤回。全程走 §14.3 统一 provenance 重算,**无需为 Ability 单写 per-space 级联**。
2. **系统级「重置 App 对我的了解」** → 唯一的系统级全清入口。
3. **源删除级联失效 + tombstone**：删源记录 / 对话 → 撤回其派生事实与行为信号；「忘掉这条」写抑制表，防下轮重抽（承接前轮删除传播结论）。

### 13.4 Style 定义与纪律（原构想中的 Soul 收敛 + 扩展）

- **定义**：表达 + 认知的个人印记——不止写作风格（句式 / 语体 / 语气），也含**观察问题的角度、思考方式、思维习惯**。（早期讨论曾叫 Soul，因偏「性格 / 心理侧写」招敏感且无明确消费者而收敛为 Style，并保留认知半边。）
- **卖点**：AI 输出（材料 / 改写 / 翻译）既像你**写**的、也像你**想**的，反「通用 AI 腔」，契合「用你的生活学语言」。
- **推断分两档**：
  - 表面写作风格（句长 / 词汇丰富度 / 正式度）→ 本地启发式 / `NaturalLanguage`，**免费、进 v1**。
  - 认知风格（角度 / 思维方式）→ 需对内容做 AI 语义分析 = **外发**，属 AI 校准能力（类比 02 方案 B）：走决策 #10 + plan 09 预览 + 最小发送 + opt-in，**后置增量，不进纯本地 v1**。
- **隐式用，不下侧写判决**：Style 隐式塑造输出，**不**作为「思维 / 人格侧写」展示给用户（同 02「不贴标签、不下判决」红线）。
- **干净信号取源语言**：目标语表达受能力限制，把「能力受限」误读成「风格选择」是同型闭环自证（见 02 §13.1）→ 目标语侧打低置信度。

### 13.5 Style ↔ Ability 下投影耦合（2026-06-14 用户新增，重要）

- Style 持**完整（源语言）印记**；母语写作自如（修辞、旁征博引），目标语写作早期受水平限制（只能基础写作）。
- **应用规则**：把 Style 用于目标语改写 / 生成时，须经**当前 Ability 水平下投影**——按水平适当**降低风格改写要求、循序渐进（i+1）**，不把母语丰富度强加给初学者输出。
- 这是 Style 消费者对 Ability 的**单向只读耦合**（平级 / 平层不等于隔离），与语伴 i+1（03 §3.9）同源。
- **双向纪律收口**：目标语既是 Style 信号的**坏来源**（混淆，§13.4），也是 Style 应用的**受限目标**（不可强加母语丰富度）。

### 13.6 隐私重定义（2026-06-14 用户定稿）

- **隐私本体**：无第一方服务端、不收集不存储用户数据、用户自带 AI Provider 与存储、全本地运行。
- 据此，**在设备上、为用户、留在设备**地分析 Style / Memory / Ability **不构成「收集」意义的隐私问题，属产品必须**（修正前轮把「本地分析」当「窥探」的措辞）。
- 但**两条边界不随之消失**：
  1. **出设备到 Provider（含用户自配 Provider，仍是第三方）** 仍受决策 #10 + plan 09 预览 + 最小发送约束。本地算 Style 免费；把蒸馏后的风格 / 记忆送进 prompt 是外发，受管。
  2. **静态集中是「安全」而非「收集」问题**：系统级跨空间 = 最浓缩全人 PII，设备失窃 / 备份泄露仍可一锅端 → §12.4 整库 `FileProtection` / 字段隔离决策**保留**，重贴标签为「本地静态数据安全」。
- 统一「查看 / 删除 App 对我的了解」入口重定位为**透明与掌控**特性（非隐私违规补救）。
- **建议合并为一次产品定位修订**（连同 02 自适应卖点、03 语伴练习模态），统一写回 `product-main-reference.md`、spec 008、ADR-005、决策 #10：隐私承诺从「我们什么都不分析」收紧为「**一切留在你设备、归你掌控，不外发不预览不发送**」。

### 13.7 可重建性三级梯度（强化 §12.4 与前轮结论）

- **Ability 真派生**（行为日志廉价重算）→ **Memory 准原始**（AI 抽取、源可删）→ **Style 准原始 / 自陈**。
- 备份 / 导出 / 同步**按层分叉**：Ability local-only、不备份、可丢弃重算；Memory / Style **纳入导出 + 可恢复备份**（删库 = 永久失忆，且是最痛 PII），删除即永久 + tombstone。
- 修正 §3「同一隐私存储姿态」：三层共享**敏感度与治理入口**，**不共享持久化等级**。

### 13.8 升格与文档冲击（建议，待用户确认链路）

- 本轮已动到：跨空间删除语义、决策 #4 需补「Learner Model 横切空间、不归属单一空间」、隐私定位修订。

## 14. 第 4 轮迭代（2026-06-14）：实现形态——证据摄入与分析管线

> 本节把 §5.2「证据摄入层」具体化为可落地的存储与处理形态；仍属 idea 层。**前置闸门**：§13.6 隐私重定义须先升格权威文档（见 §14.5）。

### 14.1 状态追踪落点：专用「分析账本」，不在源表加列

- 需求成立：每条用户输入需追踪「是否已分析 / 已分析次数」（即 §5.2 证据摄入层）。
- 但**不要**把 `is_analyzed` / `analysis_count` 加成各源表（Entry / 查词事件 / 练习 / 对话消息）的列，四个硬问题：
  1. **三层 × 多分析器，单布尔表达不了**「已被 Ability 分析、还没被 Style 分析、Memory 抽过一次」。
  2. **耦合、破坏模块边界**：源表不该知道 Learner Model 的处理状态。
  3. **破坏可重建性**：Ability 是真·派生（§13.7），让派生处理状态去改源表列等于污染源数据。
  4. **无法表达分析器版本**：升版重跑判定需要 `analyzer_version`，单 count 表达不了。
- **落点**：Learner Model 名下一张**分析账本（intake ledger）**，键 `(source_type, source_id, analyzer, analyzer_version)`，记 `status / pass_count / last_analyzed_at / last_version`，**以 (类型, id) 引用源行，不在源表加列**。红利：异构源统一进一张账本、支持「源删除 → 撤回派生 + tombstone」（§13.3）、重建只动 Learner Model 命名空间。

### 14.2 「分析次数」拆成三义；粒度按层不同

- 「一次分析不够」其实混了三件事，拆清：
  1. **语料累积导致的复算**：同一条随语料变多**参与第 N 次聚合**（尤其 Style 认知模式跨多条才显现），不是「把同一条重抽一遍」。
  2. **分析器升版重跑**：靠 `analyzer_version` 判定，不是靠 count。
  3. **失败重试**：与「成功通过次数」分开，别共用一个 count。
- 分析粒度按层不同：

  | 层 | 分析形态 | 状态 / 次数模型 |
  | --- | --- | --- |
  | **Memory** | per-item 抽取（记录 → 事实） | 行级账本 + 版本；编辑 / 升版重抽 |
  | **Ability / Style** | 窗口聚合（行为日志 / 多条产出重算） | **高水位游标（cursor）增量重算**，非 per-item 旗标 |

  账本可两种并存：extraction 用行级、aggregate 用 cursor 行。

### 14.3 证据关联（provenance）做成一等公民

- 派生事实 / 信号带 `source_refs`，支撑：可解释（「凭什么这么判断」给用户看证据）、删除级联、tombstone（§13.3）。
- **粒度警示**：Memory 事实证据是**单条 FK**；Ability / Style 证据是**一批分布（证据集 + 权重）**——schema 不得强制所有派生结果都挂单 FK。

### 14.4 外发纪律（属 AI 校准档，非本地档）

- 真正发请求时：只发**增量 delta**（未分析的新内容），不重复灌全库；排除「私密」标签 / 照片原图；本地预筛优先；走 plan 09 预览 / 日志 + 最小发送（对齐 02 §5 方案 B）。

### 14.5 隐私是前置闸门 + 三步排序

- 本方案的「自动（累计 / 定时）发分析请求」是**后台自动外发**，当前决策 #10（敏感内容仅显式触发才发）**不允许** → 必须先把 §13.6 隐私重定义**升格为权威 ADR / spec / product-main-reference**，确立：自动画像分析 = **显式 opt-in**；开启动作即 #10 的「显式触发」；其内最小发送 + plan 09 + 默认关闭。
- **纯本地启发式（零外发）不触 #10，可先行**（= 02 的 v1）。
- 排序：**① 隐私修订（权威）→ ② Learner Model 架构（ADR / architecture：三层 + 分析账本 + provenance + 删除 / tombstone）→ ③ 拆 plan**：v1 本地账本 + 本地启发式（不必等隐私修订）、v2 opt-in AI 分析管线（门控在 ① 之后）。
- 现状对照：已有 `memory_candidates` 是**用户显式「生成 / 重新分析」**产出（贴合 #10）；本方案新增的是**自动后台**维度，故需先开隐私闸。

### 14.6 本轮新增待决点

- 分析账本是「行级 + cursor」双形态，还是统一抽象？
- 定时 vs 累计阈值的默认触发策略与阈值（每层是否不同）。
- 复算的幂等 / 去重，与「同一证据不重复计权」机制。
- Ability 的分区键（按语言 vs 按空间）与其删除生命周期——见下轮讨论（§13.2 / §13.3 待据此细化）。
