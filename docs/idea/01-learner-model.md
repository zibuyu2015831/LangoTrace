## 1. 一句话定位

> 学习者模型是语迹内部一个**本地优先、持续演进**的子系统，统一承载「App 对用户的、不断积累的理解」：包括**能力画像**（用户的语言水平、知识覆盖、常犯错误）与**关系记忆**（用户的生活事实、偏好、目标）。它从用户的真实记录、对话、练习中派生，并作为**唯一可信的用户上下文来源**，喂给材料生成、解释模式、练习、复习、进步可见与「语伴」。

它对应智能辅导系统（ITS）经典三元组中的 **Learner Model**（另两个是领域模型、教学模型）。

---

## 2. 关键定位：平级子域，而非父子从属

最初的设想是「水平评测是关系记忆模块的一部分」。本文件**纠正这一从属关系**：

- **关系记忆**（记得你养了猫、在学吉他）本质偏 **语伴专属**、服务对话连续性。
- **水平评测**是**横向能力**，服务全 App（材料生成、解释模式、练习、复习、进步可见），不依赖语伴。

若让横向的水平评测从属于偏垂直的关系记忆，会把全局能力塞进一个功能特性之下，造成依赖与语义错位（材料生成要用水平信号却要穿过「关系记忆」）。

**正确抽象**：两者都是「App 对用户的理解」，即 Learner Model 的**两个平级子域**：

- **A. 能力画像（Proficiency Profile）** —— 横向，广泛消费。详见 [`02-dynamic-proficiency-assessment.md`](02-dynamic-proficiency-assessment.md)。
- **B. 关系记忆（Relationship Memory）** —— 初期由语伴驱动，可复用。源自 [`03-conversation-partner.md`](03-conversation-partner.md) §3.11。

## 3. 必要性

**判断准则：当「关于用户的派生知识」存储 ≥ 2 个、且治理姿态相同时，抽出公共模块开始划算。**

两个子域高度共享：

- **同源证据**：都吃 记录 / 语伴对话 / 练习 / 记忆候选 同一批信号。
- **同一隐私存储姿态**：高敏感、本地优先、默认不同步、派生可重建、可查看、可删除、按语言空间隔离。
- **同一批消费者**：语伴（人设上下文 + 难度）、材料生成、练习、水平总览页。
- **同一治理窗口**：用户「查看 / 导出 / 删除 App 对我的了解」应是**一个**统一入口，而非散在多处。

不抽模块的代价：两个子域各自重造「读取用户数据 → 派生 → 存储 → 隐私边界 → 展示 → 删除 → 按空间隔离」，消费者要分别接多个 store，隐私边界还可能不一致。

对一个**本地优先、隐私是北极星**的产品，「有一个可审计的、唯一的『我们了解你什么、存在哪、怎么删』的地方」本身就是**隐私卖点**（可呼应动态水平评估 §7.2 的智能性叙事）。

> 必要性结论：**中高，且随子域增多而上升**。只有能力画像一个子域时，模块是过度设计；关系记忆的加入正是「该抽模块」的临界点。

---

## 4. 可行性

- **架构上可行**：它是叠在现有证据（记录、`memory_candidates` 已在 GRDB）之上的**增量子系统**，不需推翻现有模块；新增 Core 模型 + GRDB 表 + 服务 / Provider seam。
- **时序张力（必须正视）**：
  - 能力画像建议**先于**语伴做（语伴依赖它）。
  - 关系记忆**随 / 后于**语伴做（它是语伴对话连续性特性）。
  - 两者同属一个模块 → 模块无法「先于语伴整体完成」。
- **缓解（先立边界、增量填充）**：依 `CLAUDE.md` 1.2「首版可限功能范围，但底层边界要预留」——**现在就先把模块边界 / 存储命名空间 / 查询 API 立起来，先只填充「能力画像」子域**；关系记忆等语伴落地时填进同一边界，无需重写。

## 5. 实现形态

### 5.1 模块与子域
**模块：`学习者模型 / Learner Model`（按语言空间维护）**

- **A. 能力画像 `ProficiencyProfile`**：CEFR 估计 + 置信度、分技能（理解 vs 产出）、知识覆盖、错误模式、趋势、来源标记。（细节见动态水平评估构想）
- **B. 关系记忆 `RelationshipMemory`**：用户生活 / 偏好 / 目标的语义事实集合，例如 `{ kind: 生活事实 / 偏好 / 目标 / 人际, text, salience 显著度, source, lastSeen, confidence, scope }`。
- **(待议) C. 掌握状态**：`memory_candidates` 的「已掌握 / 待巩固」状态有两栖性（见 §6）。

### 5.2 模块提供的公共基础设施
- **证据摄入层**：统一事件 / 观察者接口，被 记录保存 / 分析完成 / 练习完成 / 语伴每轮 喂入。
- **存储**：GRDB 表（`learner_proficiency`、`learner_memory_facts`、评估历史），local-only、排除同步、可重建、按空间外键、随空间级联删除。
- **查询 API `LearnerContextProvider`**：消费者问「现在该知道关于这个用户的什么」（难度信号 + 相关个人事实），语伴 / 材料生成 / 总览页都查它，而非各接多个 store。
- **唯一治理点**：水平总览 / 学习画像页（动态水平评估 §7.1）是本模块的「窗口」；并在此**集中执行**决策 #10 / 本地优先——所有「哪些个人数据可进 prompt」一处把关。

### 5.3 关系记忆专有逻辑
- 对话 → 候选事实抽取、去重合并、显著度衰减、用户可编辑 / 删除、「忘掉这条」。
- **`scope / visibility` 标记**：区分「全局可用」与「仅语伴可用」，避免材料生成莫名其妙用到「你猫的名字」这类只对对话有意义的事实。

## 6. 与 `memory_candidates` / plan 10/11（记忆库）的边界

防止与「记忆库」打架，须划清：

- **`memory_candidates` / SRS 复习队列 = 「要学什么」（领域 + 调度）**，**不**并入学习者模型；
- 但它是能力画像的**关键证据来源**（难度分布、错误模式），学习者模型**读它**；
- **两栖点**：item 的「已掌握 vs 待巩固」**状态**属学习者模型（「你会什么」），**调度机制**属 SRS；建议两者通过 item id 关联，归属在正式拆方案时定清。

## 7. 与核心决策的关系（实施前必须处理）

1. **架构级判断 → architecture note，定边界则需 ADR**：新增子系统、统一用户上下文来源，建议先落 `docs/architecture/notes/`；确定立模块边界后升格 `docs/architecture/` + ADR。
2. **细化决策 #6**：能力画像把「水平」从一次性静态值变为持续演进值（见动态水平评估 §8.1）；本模块是其载体。
3. **本地优先（#11 / ADR-005）/ 派生不同步（#12 精神）**：学习者模型是可重建派生数据，默认 local-only、默认不同步，但聚合高敏感语料，必须经 Repository 边界、可查看、可删除。
4. **隐私 #10 集中把关**：本模块是「哪些个人数据进 prompt」的唯一执行点；任何外发（AI 校准 / 关系记忆抽取）走 Provider 抽象 + plan 09 预览 / 日志 + 显式同意 + 最小发送。
5. **泄露集中点风险**：集中存「关于你的一切」既是治理优势也是单点风险，必须配套统一查看 / 删除 /（默认不）导出。

## 8. 复用 vs 新增工作

### 8.1 高复用 / 已有
- `memory_candidates`（difficulty / kind / 错误模式，已落库）作为核心证据。
- `LanguageLevel` + `ExplanationLanguageMode.derive` 的 level → 体验映射框架。
- Apple `NaturalLanguage`（语种 + 文本复杂度）。
- Provider 抽象 + 请求预览 / 日志（plan 09）。

### 8.2 真实新增
- **模块边界 / 命名空间**：Core 模型聚合 `LearnerProfile`（含 A、B 子域）；持久化在 Data；AI 抽取 / 校准在 AI；一个协调服务。模块归哪个 Swift Package（新建 `LangoTraceLearnerModel` 还是跨 Core/Data 命名空间）待定，见 §11。
- **证据摄入层 + `LearnerContextProvider` 查询 API**。
- **GRDB schema**：proficiency、memory facts、评估历史；local-only、排除同步、级联删除。
- **关系记忆抽取 / 去重 / 衰减 / scope 标记**。
- **统一治理 UI**：总览页 + 「管理 / 删除 App 对我的了解」。

## 9. 大致实施路线（先立边界、增量填充）

> 方向性路线，非承诺；正式拆解时各自走 plan + 自审核 + 用户确认。

- **第 0 步（定位）**：architecture note 立模块边界；细化决策 #6 的 ADR（按需）。
- **第 1 步（先填能力画像，先于语伴）**：在 Learner Model 边界下落地 `ProficiencyProfile` + 证据摄入 + `LearnerContextProvider`（仅返回难度信号）；接入材料生成 / 解释模式。等价于动态水平评估构想的 MVP，但**建在统一模块边界内**。
- **第 2 步（总览页 + 进步可见）**：水平总览 / 学习画像页（动态水平评估 §7.1）作为模块窗口。
- **第 3 步（填关系记忆，随语伴）**：`RelationshipMemory` 子域 + 对话抽取 + scope 标记；`LearnerContextProvider` 扩展返回相关个人事实，供语伴人设上下文。
- **第 4 步（增量）**：AI 校准（能力画像）、向量化覆盖、跨子域的统一治理与导出控制。
