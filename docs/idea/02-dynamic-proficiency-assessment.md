## 1. 一句话定位

> 动态水平评估是一项**本地优先、持续运行**的基础能力：依据用户的真实语料与学习行为，**周期性或在累计一定素材后**动态重估其目标语水平，输出一个比单一 CEFR 自评更准确、更细、可演进的「能力画像」，为难度自适应、选材、解释模式、练习、复习排序、进步可见以及未来的「语伴」提供**统一、可信的水平信号**。

它不是一次性分级测验，而是**贯穿使用过程、悄悄校准**的内部模型。

## 2. 为什么是「基础能力」，且应排在「语伴」之前

### 2.1 现状：水平信号已经承重，却建立在一次性猜测上（已实地确认）
- `LanguageLevel` 是 CEFR 枚举（`A1…C2`，默认 `B1`），**仅在首次启动 onboarding 设定一次**（`OnboardingDraft.level` → `LanguageSpace.level`），之后只能在语言空间编辑里**手动改**，**不会随使用动态更新**。
- 这个静态值**已经在驱动真实体验**：`ExplanationLanguageMode.derive(from:)` 已按 level 把阅读解释分成「源语言 / 双语桥接 / 目标语沉浸」三档（`ReadingDocumentStore` 已消费）。也就是说，**体验已经依赖 level，而 level 只是一次主观猜测**。
- 现有学习材料分析产出的 `memory_candidates` 已带 `difficulty`（easy / medium / hard）与 `kind`（词 / 短语 / 句型 / 语法点 / **错误模式**），并已落库——**这本身就是一条免费的、已存在的水平证据流，目前却没有被用来反推水平**。

### 2.2 静态自评的固有缺陷
1. **主观失真**：用户常误估自己（高估或低估都常见）。
2. **单一维度**：一个 CEFR 字母覆盖全部技能，但自学者「读得懂、说不出」的产出 / 理解鸿沟极大。
3. **静态过期**：用户会进步，自评不会自己更新；空间用得越久越失真。
4. **粒度太粗**：6 个档位说不出「具体哪些词 / 语法已掌握、哪些待巩固」。

### 2.3 为什么应在「语伴」之前
- 「语伴」的难度自适应（[`03-conversation-partner.md`](03-conversation-partner.md) §3.9）**明确依赖一个好的水平信号**；若建立在陈旧的一次性自评上，等于把失败模式焊死在新功能里。
- 水平信号是**横向地基**：学习材料生成难度、解释语言模式、练习选材、复习排序都已经或将要消费它。把这条信号修准，**一次性抬升所有下游功能**，而不止「语伴」。
- 符合 `CLAUDE.md` 1.2「基础设施首次落地应采用长期可扩展方案」「地基先于功能」。先有准确的「了解用户」，再谈「为用户定制」。

## 3. 应该把「水平」升级成什么：能力画像（Proficiency Profile）

把单一 CEFR 字母升级为一个**结构化、带置信度、可演进**的画像（**系统级、按 language code 维护**，同语言多空间共享一份，见 §14 与 [`01-learner-model.md`](01-learner-model.md) §13.2；旧版「按语言空间维护」已废弃）：

1. **总体 CEFR 估计 + 置信度**：保留与现有 `LanguageLevel` 枚举的向后兼容（仍可映射回 A1–C2），但附带「估计依据是否充分」的置信度。
2. **分技能估计（理解 vs 产出，至少二分）**：阅读 / 听力（理解）与写作 / 口语（产出）可能差异巨大；至少区分 receptive vs productive，避免用一个数字掩盖鸿沟。
3. **知识覆盖摘要**：已掌握 / 巩固中 / 未掌握的词汇、句型、语法点、**高频错误模式**——可直接由现有 `memory_candidates` 的 difficulty / kind 分布聚合而来。
4. **趋势**：近期在进步 / 持平，以及最近评估窗口，用于「进步可见」（呼应语伴 §3.12）。
5. **来源标记**：`selfReported`（自评种子）/ `assessed`（系统评估）/ `blended`（融合），便于透明与可解释。

## 4. 证据来源（仅限用户产出 / 行为，排除 AI 生成物）

> **2026-06-13 用户定稿原则（架构红线）**：评估水平所用的**材料必须是用户的输入 / 行为，绝不能是 AI 生成的内容**。AI 生成的学习文本、AI 赋予的 `difficulty` 标签、AI 选定的候选词，**一律不得**作为水平证据——否则构成 §13.1 的闭环自证（`level → AI 生成难度 → 反推 level`）。
>
> **架构师细化（刺激 vs 响应）**：一条 AI 生成的 item 可以充当**刺激**（如 SRS 复习卡片），但只有**用户对它的响应**（回忆对错、是否查词、转写是否正确）才是信号；AI 对它的**判断**（难度标签）永远不是。据此区分「有效证据」与「禁用证据」。

### 4.1 有效证据（用户产出 / 行为，本地优先）

| 证据 | 现状 | 信号类型 | 独立于被估 level |
| --- | --- | --- | --- |
| 用户用**目标语**书写的记录（长度、句法复杂度、自纠错） | 部分（需判定语种） | 产出能力（强） | 是 |
| **查询的单词 / 表达及频率**（长按索取翻译 / 解释、重复查同一词） | 随阅读 / 语伴落地 | 理解盲点、未习得词（高频行为信号） | 是 |
| 「语伴」对话中用户的**目标语**发言 | 语伴落地后 | 产出能力（强） | 是 |
| 练习中用户的**产出**（听写转写准确率、回译译文质量、跟读评分） | 录音已有、**评分待实现** | 产出 / 理解 | 是 |
| onboarding 自评 level | 已有 | **仅**冷启动先验 / 种子 | —（先验） |
| SRS 复习**回忆结果**（卡片可 AI 生成，只取用户回忆对错） | plan 10 / 11 后 | **仅覆盖**（次级），不进 band 估计 | 部分 |

### 4.2 禁用证据（AI 生成物，不得用于估水平）

| 来源 | 为何禁用 |
| --- | --- |
| `memory_candidates.difficulty`（AI 赋值的难度标签） | AI 主观判断，且分布受 level 驱动 → 闭环自证 |
| AI 生成的学习文本 / `grammarNotes` / `keyPoints` 本身 | AI 产出，非用户能力体现 |
| AI 选定「哪些词算候选」 | 选择反映 AI 而非用户 |

> `memory_candidates` 仍可用于**「学习材料覆盖」的展示**（用户接触 / 复习过哪些项），但 difficulty 标签**不进入水平 band 估计**；进入估计的只有「用户是否查它、复习是否回忆正确、用户自己写 / 说了什么」这类用户响应。展示时须与「你的真实错误（来自你自己的目标语产出）」**明确区分**，不可混为一谈。

要点：有效证据多数**已经或即将在本机由用户产出**，动态评估是「聚合用户真实行为」，既不采集新数据，也不读 AI 的自我判断。

## 5. 评估机制：三种方案与推荐

- **方案 A：纯本地启发式 / 统计**（不发起 AI 请求）。聚合候选难度直方图、错误率、词汇覆盖、用 Apple `NaturalLanguage` 估文本复杂度。**确定、免费、完全私密**，但较粗。
- **方案 B：AI 周期性校准**。把**近期本地信号的摘要**（聚合统计 + 经用户同意的少量样例句，**非原始敏感内容**）送 Provider 给出 CEFR 估计与理由。质量更高，但涉及隐私与成本，必须遵守核心决策 #10（明示触发 / 最小发送）。**前置闸门（2026-06-14）**：方案 B 的「自动 / 周期触发」属**自动后台外发**，当前决策 #10 不允许；必须先把 [`01-learner-model.md`](01-learner-model.md) §13.6 隐私重定义升格为权威 ADR / spec 后才能解锁，开启动作本身即 #10 的「显式触发」+ opt-in + 默认关闭（见 01 §14.5、本文件 §14）。
- **方案 C（推荐）：混合**。本地启发式**持续**维护画像（默认永不外发任何内容）；AI 校准为**可选、用户显式触发、周期性**的增强。

> 推荐 C：与本地优先 / ADR-005、决策 #10 一致；初版可只做 A 的本地启发式，B 作为后续可选增量。

## 6. 触发节奏

- **持续累积**：每当有新的分析 / 练习 / 记录事件，增量更新画像（本地廉价）。
- **周期性重估**：例如每周，或**累计阈值触发**（新增 N 条候选 / M 条目标语记录 / K 次练习后）——即用户设想的「可定期或累计一定素材时」。
- **手动**：设置中「重新评估我的水平」。

## 7. 评估结果如何反哺（下游消费者）

- 学习材料**生成难度**（写入 Prompt 受控片段）。
- **解释语言模式**：`ExplanationLanguageMode.derive` 当前吃静态 level，应改吃**评估后水平**（注意：这是对现有行为的改动，需触发文档影响检查）。**时序：此改动属 band 重估 = v2；v1 完全不碰 `derive()`，仍吃静态 level**（见 §13.2 / §13.3 / §14）。
- 练习**选材与难度**。
- 记忆**复习排序**（SRS 难度，呼应 plan 10/11）。
- 「语伴」**回复难度**（本需求的直接动因）。
- **Style 的目标语改写 i+1 下投影**：Style 应用到目标语生成 / 改写时按当前 Ability 水平降级、循序渐进，不把母语丰富度强加给初学者（[`01-learner-model.md`](01-learner-model.md) §13.5；2026-06-14 新增消费者）。
- **进步可见** UI（趋势 / 覆盖）。

### 7.1 专属页面：水平总览 / 学习画像
评估结果除了在内部调难度，还应有一个**面向用户的归宿页面**，把「了解你」可视化——否则评估对用户是黑箱，也浪费了它能带来的成就感与方向感。

- **页面定位**：一个「我的语言水平 / 学习画像」页（按当前语言空间），把 §3 能力画像呈现给用户。
- **核心内容**：
  - **总体水平与置信度**：当前估计的 CEFR 区间 + 趋势（进步 / 持平），克制呈现，避免「降级判决」（见 §8.6）。
  - **分技能画像**：理解 vs 产出（阅读 / 听力 / 写作 / 口语）的相对强弱，直观点出「读得懂但说不出」这类鸿沟。
  - **常犯错误 / 学习盲点**：聚合 `memory_candidates` 中 `kind = errorPattern` 与高频语法点 / 词汇盲区，列成「你最近常错的点」「待巩固清单」——这是页面最具行动价值的部分。
  - **知识覆盖**：已掌握 / 巩固中 / 未掌握的词汇与语法点概览。
  - **进步轨迹**：基于评估历史的时间线 / 趋势（呼应「进步可见」与语伴 §3.12 对话小结）。
- **行动闭环**：盲点 / 错误项可一键**加入记忆库 / 生成针对性练习**（接 plan 10/11 与练习），让页面不止于展示，而是「看见问题 → 立即练」。
- **入口与平台**：三端各自合适的入口（如设置内 / 个人页 / 学习桌面卡片），遵循导航 spec 002 与 `docs/workflows/add-platform-screen.md`。
- **隐私与情绪边界**：页面数据全部本地派生；呈现以**成长与覆盖**为主、避免挫败感（见 §8.6）；是否默认展示「水平变化」需克制（见 §12）。
- **依赖**：依赖 §3 画像与 §4 证据已具备一定积累；空记录 / 证据稀疏时优雅退化为「继续记录以解锁画像」引导（与语伴冷启动 §3.10 同源问题）。

### 7.2 「自适应」作为产品卖点，以及是否还需要明确等级

**结论倾向（待用户拍板）**：把「自适应」作为产品智能性的卖点**成立且契合北极星**；并据此建议**淡化而非取消**明确的 CEFR 等级——让「自适应 + 成长信号」成为用户主界面主角，明确等级降为可选、温和呈现的配角。

#### Q1：作为宣传点
- **成立**：「懂你水平、自动调整难度」是主流学习工具公认的智能性卖点；叠加语迹的**本地优先、用真实生活语料、在设备上自学你的水平**，是竞品（多为云端 / 静态自评 / 显式测验）做不出的差异化，且与「用生活记录学习语言」一致。
- **门槛（隐形即无效）**：宣传它就必须让用户**真切感知**到自适应。因此一旦作为卖点，§7.1 呈现页与「内容已按你水平调整」的可感反馈成为**必需项**而非可选。
- **真实性**：作为对外承诺，自适应必须真生效且可见，不能是营销话术；这也抬高了本能力的质量与排序优先级。
- **写回要求**：若确认作为卖点，属产品定位层判断，需回写 [`product-main-reference.md`](docs/product-main-reference.md) 与入口文档，并与「产品不是 AI 聊天工具」等定位表述协调。

#### Q2：是否还需要明确等级 —— 建议「降级保留」而非「彻底取消」
- **取消的合理之处**：等级（A1–C2）是**静态判决 / 身份标签**，天然招致比较与「降级打击」；而「自适应」是**过程 / 行为**，可只展示「系统在持续为你调整」而从不钉死字母。**淡化标签恰好顺带消解 §8.6 的打击信心问题**——没有要掉的标签，就没有降级判决；「我们不给你贴标签，内容始终刚好适合你」本身可作差异化叙事。
- **不宜彻底取消的四个理由**：
  1. **冷启动需种子**：无证据时仍需初始先验，决策 #6 首启自评不能消失（但可从「选 A1–C2」改为更轻的阶段化措辞，如「初学 / 能日常交流 / 较流利」，内部再映射）。
  2. **用户心智锚点**：不少学习者想知道自己大致水平、想设「我要到 B2」的目标；完全藏起会失去方向感与成就锚点。
  3. **外部互通**：CEFR 是考试 / 课程通用语，粗略定位有现实用处。
  4. **内部始终需要**：即便不展示，系统也需连续水平信号驱动难度。
- **建议综合**：
  - **内部**：始终维护连续水平信号（§3）。
  - **onboarding**：保留自评作为「起点种子」（决策 #6），措辞轻量化、强调「这只是起点，之后会自动校准」。
  - **用户主界面（主角）**：自适应行为 + 成长信号（覆盖、已掌握词汇、已纠正的错误、趋势、「今天的内容已按你的水平调整」）。
  - **明确 CEFR 等级（配角）**：作为**可选、可查看、温和呈现的参考**（如「约 B1，且在上升」），绝不做头条、不做降级判决；是否展示可设为 opt-in。

## 8. 与核心决策的关系（实施前必须处理）

1. **细化决策 #6（首次启动自评）→ 可能需要 ADR**：决策 #6 规定首次启动做一次水平自评。本需求把「水平」从**一次性静态值**升级为**持续演进的画像**，是对该决策的实质细化，建议以 ADR 写明：自评是**种子 / 先验**而非最终值；系统可在内部使用评估后水平；二者关系（覆盖 / 并存 / 仅建议）需明确。
2. **本地优先（#11 / ADR-005）**：评估默认在本机进行，输入语料默认不外发；任何外发走 §5 方案 B 的显式同意与最小发送。
3. **派生数据与同步（#12 精神）**：能力画像是**可由本地记录 + 候选重建的派生数据**，默认 **local-only、默认不同步**；但它聚合自高敏感个人语料，不能当作普通无敏感缓存随意处理，必须经 Repository 边界管理、可查看、可删除。
4. **隐私 #10**：若启用 AI 校准（方案 B），属「明示触发对应 AI 能力」才发送，且只发聚合摘要 / 经同意样例。
5. **Provider 抽象（#8）**：AI 校准走 Provider 抽象，复用请求预览 / 日志（plan 09）隐私边界。
6. **不打击信心（产品红线）**：避免向用户直接呈现「你从 B1 掉到 A2」式判决。优先展示**成长与覆盖**而非降级结论；面向用户的「水平变化」展示应克制或 opt-in，内部难度调节可先于公开标签生效。**§7.2 的「自适应为主角、明确等级降为配角」方向正是对这条红线的产品级解法**——淡化标签即消解降级判决。
7. **若自适应作为对外卖点 → 触及产品定位 / 主参考**：见 §7.2，需回写 `product-main-reference.md` 与入口文档，且承诺必须有真实能力支撑。

## 13. 架构师评审（2026-06-13，基于代码实地核对）

> 站在系统架构师角度对本构想的压力测试。已核对：`ExplanationLanguageMode.derive(from:)` 确为基于稳定枚举的**纯函数**（`Packages/LangoTraceCore/Sources/LangoTraceCore/ExplanationLanguageMode.swift`，A1/A2→源语言、B1/B2→双语桥接、C1/C2→目标沉浸）；`memory_candidates.difficulty` 由材料生成时 **AI 赋值**并落库（`GRDBLearningContentRepository`）；`ReadingDocumentStore` 的解释缓存 key 已含 `explanationMode`。跨文件结论见 [`README.md`](README.md) §6。

### 13.1 测量效度的致命点：评估与其消费者之间的闭环自证（文档未覆盖）
最大风险不在实现，而在**效度**。`memory_candidates.difficulty` 由 AI 在材料生成时赋值，而**材料生成难度本身受 level 驱动**（§7）。于是形成闭环：`level → 材料生成难度 → 候选难度分布 → 反推 level`。若告诉 AI「用户 A2、按 A2 生成」，候选必然偏 A2，评估器据此「确认」A2——水平被**永久焊死**、无法反映真实进步。
- **结论（已被 2026-06-13 用户定稿强化为红线，见 §4）**：AI 生成物（候选 difficulty 标签、AI 学习文本）**禁止**用于估**水平**；候选最多用于「学习材料覆盖」的**展示**，且只取接触 / 复习记录、不取 difficulty 标签。
- 估水平**只用**不在被估 level 下游的**用户产出 / 行为**：目标语写作、查词及频率、语伴目标语发言、练习产出评分。§4 已据此重构为「有效证据 / 禁用证据」两表。

### 13.2 因此建议把 v1 拆成「覆盖视图（安全）」与「水平重估（高风险，延后）」
- **v1 = 行为信号 + 覆盖展示（安全、合规、高 ROI）**：以**用户行为**为骨架——主力是**查词 / 索取解释的频率**（高频、几乎人人都有、完全独立于 level），辅以用户**目标语产出**（写作 / 练习产出，稀疏但强）。覆盖展示可叠加 `memory_candidates` 的**接触 / 复习**记录（**不取 difficulty 标签**）。「常犯错误」清单应来自**用户自己目标语产出**中的错误，而非 AI 候选。**零 band 重估、零外发、无闭环。**
- **v2 = 水平 band 重估（高风险，延后）**：重估 CEFR band 并回灌 `derive()`，需独立信号充分、需回归，先解决信号独立性与稀疏性（§13.4）。
- 该拆分规避 v1 闭环，也使 §10「第 1 步内部消费 derive」降为 v2。注意：v1 的高 ROI 来源由「聚合候选难度」**改为**「聚合用户查词行为 + 用户目标语产出」，与 §4 红线一致。

### 13.3 `derive()` 改吃演进值是一次「体验在脚下漂移」的改动，需迟滞处理
当前 `derive(from:)` 是稳定枚举的纯函数；改吃**演进**的评估值后，同一句的阅读解释模式会**跨会话变化**（昨天双语桥接、今天目标沉浸）。缓存 key 含 mode 会**正确失效**，但**用户感知层**会出现「我的解释怎么突然换语言了」。**建议**：评估值经**迟滞 / 粘滞映射**驱动 mode（达到稳定阈值才切档 + 最小停留窗口），而非逐次更新即切；或只对**新内容**应用新档。§7 已标「需触发文档影响检查」，但未点名这一不稳定性，应在改动 plan 中显式纳入。

### 13.4 结构性事实：母语记录占绝大多数 → 产出信号天然稀疏
产品核心闭环是「记录你的生活」，而人用**母语**记录生活是常态（这正是生活记录的本意）。于是最丰富的**产出**信号（目标语写作）对多数用户**长期稀疏**。这不是 bug，是结构属性：
- v1 应**以理解 + 覆盖为主**，产出估计标注**低置信度**、机会性采集，而非假装能测产出。
- **反转一个依赖**：语伴会**生成目标语产出**，因此语伴可能是产出维度的**主要证据来源**。这弱化了「评估严格先于语伴」的单向性——**产出维度上两者协同演进**：评估先上线（服务理解 / 覆盖 / 难度），语伴落地后**回灌**产出证据补齐画像。建议在 §11 排序中体现这一双向性，而非纯单向「评估 → 语伴」。

### 13.5 卖点与定位：与语伴合并为一次定位修订，避免割裂
若确立「自适应」为对外卖点（§7.2 Q1）需改 `product-main-reference.md`；语伴定位变更（03）也要改它。**不要两份 idea 各自独立改主参考**，否则产品故事割裂成「会给你画像 + 会陪你聊天的 AI」（既 me-too 又略显窥探）。**建议合并为一次**定位修订，统一叙事为「本地优先、从你的生活**自适应**学习，并提供一个**扎根记录**的对话练习模态」。

### 13.6 新增待决点
- v1 是否采纳「覆盖视图先行、CEFR 水平重估延后」拆分（§13.2）？
- `derive()` 改吃评估值时的迟滞策略：稳定阈值 + 停留窗口 / 仅新内容 / 不切档只调生成难度（§13.3）？
- 是否接受「产出维度评估与语伴协同演进」，并据此放宽「评估严格先于语伴」（§13.4）？
- §4 证据表是否按「是否独立于被估 level」重新加权（§13.1）？

### 14.1 三个统领判断（决定其余小项）

1. **一次定位修订，不是三次**：自适应卖点（本文件）、三层隐私重定义（01 §13.6）、语伴练习模态（03）合并为**一次** `product-main-reference.md` 修订。统一叙事「本地优先、从你的真实生活**自适应**地学你的语言」；**「用生活记录学语言」仍是头条**，自适应是其智能性 + 隐私性**证据**，不抢北极星。
2. **v1 = 纯本地、零外发、不重估 band、只做覆盖 + 行为信号**：同时满足闭环效度（§13.1）、隐私闸门（01 §14.5）、母语稀疏（§13.4）、不打击信心红线。凡触发「外发 / band 判决 / `derive()` 漂移」者一律推 v2 并加门控。
3. **本文件不单独出 ADR、不单独修主参考**：折叠进 **01 的 Learner Model ADR**（含决策 #6 细化）；排序遵循 01 §14.5：**① 隐私修订（权威）→ ② Learner Model 架构 ADR → ③ 拆 plan**。

### 14.2 待决项逐项定稿

| §12 待决项 | 定稿推荐 | 一句话理由 |
| --- | --- | --- |
| 自适应作卖点 | **采纳**，但降为「北极星的证据」而非新头条；并入一次定位修订；§7.1 总览页因此**升为必需**（承诺须可感） | 真差异化但不抢北极星，且承诺必须可见 |
| CEFR 等级去留 | **降级保留**：自适应为主角，明确等级为可选、温和、opt-in 配角，**永不降级判决** | 消解信心红线，同时保住冷启动 / 锚点 / 互通 |
| 自评 vs 评估关系 | **评估覆盖「内部难度信号」，永不覆盖「用户可见标签」**；用户标签**保留可手动编辑**，评估只「建议 / 并存」、绝不静默改写 | 内容背后悄悄适配、标签由用户掌控，才诚实 |
| onboarding 措辞 | **轻量阶段化**（初学 / 能日常交流 / 较流利）+ 内部映射 CEFR +「仅起点，会自动校准」 | 降定级身份感，仍保留种子（决策 #6） |
| 不打击信心策略 | **永不展示「降级」**，只展示覆盖 / 已纠正错误 / 趋势 / 成长；淡化标签 → 无可掉字母 → 结构上消灭降级判决 | 红线的产品级解法 |
| 分技能（理解 / 产出） | v1 **只做理解 + 覆盖**；产出维度标低置信度占位，待练习评分 / 语伴产出落地补（v2） | 母语记录稀疏（§13.4），早期测不准产出 |
| AI 校准（方案 B） | v1 **纯本地零外发**；方案 B 延后 v2 且**硬门控**——属自动后台外发，须等 01 §13.6 隐私重定义升格权威文档后才解锁（opt-in + 默认关闭 + plan 09 预览 / 最小发送） | 本地优先 / ADR-005 / 决策 #10 |
| 母语稀疏 / 低置信 | 证据不足优雅退化为「继续记录 / 对话以解锁产出画像」；**采纳与语伴协同演进**，放宽「评估严格先于语伴」——评估先上线（理解 / 覆盖 / 难度），语伴落地后回灌产出证据 | 产出维度双向，非纯单向 |
| `derive()` 迟滞 | **稳定阈值 + 最小停留窗口 + 仅新内容**；内部生成难度可即时随评估（不可见），可见解释档迟滞、不回溯翻缓存、不骤降。**属 v2；v1 不碰 `derive()`** | 防「体验在脚下漂移」，并把感知漂移隔离在 v2 |
| 同步 | Ability 是真派生 → **local-only、不备份、不同步、不提供 opt-in**，可丢弃重算 | 决策 #12；对齐 01 §13.7 按层分叉持久化 |
| 总览页（§7.1） | **不做第四顶层 Tab**；设置内 / 个人画像区 + 学习桌面摘要卡引流。v1 模块 = 温和总体水平 + 常犯错误 / 盲点（**来自用户自己目标语产出，非 AI 候选**）+ 覆盖 + 基础趋势；不展示降级；行动闭环「看见问题→立即练」随 plan 10/11 + 练习评分落地再接 | 守住「不是聊天 / 不堆 Tab」，盲点清单是 v1 即可交付的高价值部分 |
| 是否独立 ADR | **需要 ADR，但不独立**——折叠进 01 的 Learner Model ADR（细化决策 #6：自评 = 种子、评估 = 演进内部值、关系 = 覆盖内部难度但不覆盖用户标签） | 一处定边界，杜绝两份 idea 各改决策 #6 |
| 拆 plan / 系列位置 | 追加不重编 01–15：**① Learner Model 边界 + 覆盖视图（接 plan 10）→ ② 总览页 + 水平重估 + 分技能 → ③ 语伴（最后）**；硬门控：先关闭 2026-06-11 Mac 验证门再实现 | 依赖排序 + 不在未验证地基上叠加 |
