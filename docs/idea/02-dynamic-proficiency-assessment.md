## 1. 一句话定位

> 动态水平评估是一项**本地优先、持续运行**的基础能力：依据用户的真实语料与学习行为，**周期性或在累计一定素材后**动态重估其目标语水平，输出一个比单一 CEFR 自评更准确、更细、可演进的「能力画像」，为难度自适应、选材、解释模式、练习、复习排序、进步可见以及未来的「语伴」提供**统一、可信的水平信号**。

它不是一次性分级测验，而是**贯穿使用过程、悄悄校准**的内部模型。

## 2. 为什么是「基础能力」，且应排在「语伴」之前

### 2.1 现状：水平信号已经承重，却建立在一次性猜测上（已实地确认）
- `LanguageLevel` 是 CEFR 枚举（`A1…C2`，默认 `B1`），**仅在首次启动 onboarding 设定一次**（`OnboardingDraft.level` → `LanguageSpace.level`），之后只能在语言空间编辑里**手动改**，**不会随使用动态更新**。
- 这个静态值**已经在驱动真实体验**：`ExplanationLanguageMode.derive(from:)` 已按 level 把阅读解释分成「源语言 / 双语桥接 / 目标语沉浸」三档（`ReadingDocumentStore` 已消费）。也就是说，**体验已经依赖 level，而 level 只是一次主观猜测**。
- 现有学习材料分析产出的 `memory_candidates` 已带 `difficulty`（easy / medium / hard）与 `kind`（词 / 短语 / 句型 / 语法点 / **错误模式**），并已落库——**这本身就是一条免费的、已存在的水平证据流，目前却没有被用来反推水平**。

### 2.2 静态自评的固有缺陷
1. **主观失真**：用户常误估自己（高估或低估都常见）。
2. **单一维度**：一个 CEFR 字母覆盖全部技能，但自学者「读得懂、说不出」的产出 / 理解鸿沟极大。
3. **静态过期**：用户会进步，自评不会自己更新；空间用得越久越失真。
4. **粒度太粗**：6 个档位说不出「具体哪些词 / 语法已掌握、哪些待巩固」。

### 2.3 为什么应在「语伴」之前
- 「语伴」的难度自适应（[`03-conversation-partner.md`](03-conversation-partner.md) §3.9）**明确依赖一个好的水平信号**；若建立在陈旧的一次性自评上，等于把失败模式焊死在新功能里。
- 水平信号是**横向地基**：学习材料生成难度、解释语言模式、练习选材、复习排序都已经或将要消费它。把这条信号修准，**一次性抬升所有下游功能**，而不止「语伴」。
- 符合 `CLAUDE.md` 1.2「基础设施首次落地应采用长期可扩展方案」「地基先于功能」。先有准确的「了解用户」，再谈「为用户定制」。

## 3. 应该把「水平」升级成什么：能力画像（Proficiency Profile）

把单一 CEFR 字母升级为一个**结构化、带置信度、可演进**的画像（按语言空间维护）：

1. **总体 CEFR 估计 + 置信度**：保留与现有 `LanguageLevel` 枚举的向后兼容（仍可映射回 A1–C2），但附带「估计依据是否充分」的置信度。
2. **分技能估计（理解 vs 产出，至少二分）**：阅读 / 听力（理解）与写作 / 口语（产出）可能差异巨大；至少区分 receptive vs productive，避免用一个数字掩盖鸿沟。
3. **知识覆盖摘要**：已掌握 / 巩固中 / 未掌握的词汇、句型、语法点、**高频错误模式**——可直接由现有 `memory_candidates` 的 difficulty / kind 分布聚合而来。
4. **趋势**：近期在进步 / 持平，以及最近评估窗口，用于「进步可见」（呼应语伴 §3.12）。
5. **来源标记**：`selfReported`（自评种子）/ `assessed`（系统评估）/ `blended`（融合），便于透明与可解释。

## 4. 证据来源（全部本地、且多数已在产出）

| 证据 | 现状 | 信号类型 |
| --- | --- | --- |
| onboarding 自评 level | 已有 | 先验 / 冷启动种子 |
| 学习材料分析产出的 `memory_candidates`（difficulty / kind / 错误模式） | **已落库** | 词汇 / 语法覆盖、错误密度 |
| 句子分析 grammarNotes / keyPoints | 已有 | 语法复杂度 |
| 用户用**目标语**书写的记录（长度、句法复杂度、错误率） | 部分（需判定语种） | 产出能力 |
| 练习表现（跟读 / 听写 / 回译评分） | 录音已有、**评分待实现** | 产出 / 理解（远期接入） |
| 长按索取翻译 / 解释的频率 | 随阅读 / 语伴落地 | 理解难度代理指标 |
| 「语伴」对话输入 | 远期 | 产出能力（语伴落地后反哺） |

要点：**多数证据已经在本机产出**，动态评估更多是「聚合已有信号」，而非新造大量数据采集。

## 5. 评估机制：三种方案与推荐

- **方案 A：纯本地启发式 / 统计**（不发起 AI 请求）。聚合候选难度直方图、错误率、词汇覆盖、用 Apple `NaturalLanguage` 估文本复杂度。**确定、免费、完全私密**，但较粗。
- **方案 B：AI 周期性校准**。把**近期本地信号的摘要**（聚合统计 + 经用户同意的少量样例句，**非原始敏感内容**）送 Provider 给出 CEFR 估计与理由。质量更高，但涉及隐私与成本，必须遵守核心决策 #10（明示触发 / 最小发送）。
- **方案 C（推荐）：混合**。本地启发式**持续**维护画像（默认永不外发任何内容）；AI 校准为**可选、用户显式触发、周期性**的增强。

> 推荐 C：与本地优先 / ADR-005、决策 #10 一致；初版可只做 A 的本地启发式，B 作为后续可选增量。

---

## 6. 触发节奏

- **持续累积**：每当有新的分析 / 练习 / 记录事件，增量更新画像（本地廉价）。
- **周期性重估**：例如每周，或**累计阈值触发**（新增 N 条候选 / M 条目标语记录 / K 次练习后）——即用户设想的「可定期或累计一定素材时」。
- **手动**：设置中「重新评估我的水平」。

## 7. 评估结果如何反哺（下游消费者）

- 学习材料**生成难度**（写入 Prompt 受控片段）。
- **解释语言模式**：`ExplanationLanguageMode.derive` 当前吃静态 level，应改吃**评估后水平**（注意：这是对现有行为的改动，需触发文档影响检查）。
- 练习**选材与难度**。
- 记忆**复习排序**（SRS 难度，呼应 plan 10/11）。
- 「语伴」**回复难度**（本需求的直接动因）。
- **进步可见** UI（趋势 / 覆盖）。

### 7.1 专属页面：水平总览 / 学习画像
评估结果除了在内部调难度，还应有一个**面向用户的归宿页面**，把「了解你」可视化——否则评估对用户是黑箱，也浪费了它能带来的成就感与方向感。

- **页面定位**：一个「我的语言水平 / 学习画像」页（按当前语言空间），把 §3 能力画像呈现给用户。
- **核心内容**：
  - **总体水平与置信度**：当前估计的 CEFR 区间 + 趋势（进步 / 持平），克制呈现，避免「降级判决」（见 §8.6）。
  - **分技能画像**：理解 vs 产出（阅读 / 听力 / 写作 / 口语）的相对强弱，直观点出「读得懂但说不出」这类鸿沟。
  - **常犯错误 / 学习盲点**：聚合 `memory_candidates` 中 `kind = errorPattern` 与高频语法点 / 词汇盲区，列成「你最近常错的点」「待巩固清单」——这是页面最具行动价值的部分。
  - **知识覆盖**：已掌握 / 巩固中 / 未掌握的词汇与语法点概览。
  - **进步轨迹**：基于评估历史的时间线 / 趋势（呼应「进步可见」与语伴 §3.12 对话小结）。
- **行动闭环**：盲点 / 错误项可一键**加入记忆库 / 生成针对性练习**（接 plan 10/11 与练习），让页面不止于展示，而是「看见问题 → 立即练」。
- **入口与平台**：三端各自合适的入口（如设置内 / 个人页 / 学习桌面卡片），遵循导航 spec 002 与 `docs/workflows/add-platform-screen.md`。
- **隐私与情绪边界**：页面数据全部本地派生；呈现以**成长与覆盖**为主、避免挫败感（见 §8.6）；是否默认展示「水平变化」需克制（见 §12）。
- **依赖**：依赖 §3 画像与 §4 证据已具备一定积累；空记录 / 证据稀疏时优雅退化为「继续记录以解锁画像」引导（与语伴冷启动 §3.10 同源问题）。

### 7.2 「自适应」作为产品卖点，以及是否还需要明确等级

**结论倾向（待用户拍板）**：把「自适应」作为产品智能性的卖点**成立且契合北极星**；并据此建议**淡化而非取消**明确的 CEFR 等级——让「自适应 + 成长信号」成为用户主界面主角，明确等级降为可选、温和呈现的配角。

#### Q1：作为宣传点
- **成立**：「懂你水平、自动调整难度」是主流学习工具公认的智能性卖点；叠加语迹的**本地优先、用真实生活语料、在设备上自学你的水平**，是竞品（多为云端 / 静态自评 / 显式测验）做不出的差异化，且与「用生活记录学习语言」一致。
- **门槛（隐形即无效）**：宣传它就必须让用户**真切感知**到自适应。因此一旦作为卖点，§7.1 呈现页与「内容已按你水平调整」的可感反馈成为**必需项**而非可选。
- **真实性**：作为对外承诺，自适应必须真生效且可见，不能是营销话术；这也抬高了本能力的质量与排序优先级。
- **写回要求**：若确认作为卖点，属产品定位层判断，需回写 [`product-main-reference.md`](docs/product-main-reference.md) 与入口文档，并与「产品不是 AI 聊天工具」等定位表述协调。

#### Q2：是否还需要明确等级 —— 建议「降级保留」而非「彻底取消」
- **取消的合理之处**：等级（A1–C2）是**静态判决 / 身份标签**，天然招致比较与「降级打击」；而「自适应」是**过程 / 行为**，可只展示「系统在持续为你调整」而从不钉死字母。**淡化标签恰好顺带消解 §8.6 的打击信心问题**——没有要掉的标签，就没有降级判决；「我们不给你贴标签，内容始终刚好适合你」本身可作差异化叙事。
- **不宜彻底取消的四个理由**：
  1. **冷启动需种子**：无证据时仍需初始先验，决策 #6 首启自评不能消失（但可从「选 A1–C2」改为更轻的阶段化措辞，如「初学 / 能日常交流 / 较流利」，内部再映射）。
  2. **用户心智锚点**：不少学习者想知道自己大致水平、想设「我要到 B2」的目标；完全藏起会失去方向感与成就锚点。
  3. **外部互通**：CEFR 是考试 / 课程通用语，粗略定位有现实用处。
  4. **内部始终需要**：即便不展示，系统也需连续水平信号驱动难度。
- **建议综合**：
  - **内部**：始终维护连续水平信号（§3）。
  - **onboarding**：保留自评作为「起点种子」（决策 #6），措辞轻量化、强调「这只是起点，之后会自动校准」。
  - **用户主界面（主角）**：自适应行为 + 成长信号（覆盖、已掌握词汇、已纠正的错误、趋势、「今天的内容已按你的水平调整」）。
  - **明确 CEFR 等级（配角）**：作为**可选、可查看、温和呈现的参考**（如「约 B1，且在上升」），绝不做头条、不做降级判决；是否展示可设为 opt-in。

## 8. 与核心决策的关系（实施前必须处理）

1. **细化决策 #6（首次启动自评）→ 可能需要 ADR**：决策 #6 规定首次启动做一次水平自评。本需求把「水平」从**一次性静态值**升级为**持续演进的画像**，是对该决策的实质细化，建议以 ADR 写明：自评是**种子 / 先验**而非最终值；系统可在内部使用评估后水平；二者关系（覆盖 / 并存 / 仅建议）需明确。
2. **本地优先（#11 / ADR-005）**：评估默认在本机进行，输入语料默认不外发；任何外发走 §5 方案 B 的显式同意与最小发送。
3. **派生数据与同步（#12 精神）**：能力画像是**可由本地记录 + 候选重建的派生数据**，默认 **local-only、默认不同步**；但它聚合自高敏感个人语料，不能当作普通无敏感缓存随意处理，必须经 Repository 边界管理、可查看、可删除。
4. **隐私 #10**：若启用 AI 校准（方案 B），属「明示触发对应 AI 能力」才发送，且只发聚合摘要 / 经同意样例。
5. **Provider 抽象（#8）**：AI 校准走 Provider 抽象，复用请求预览 / 日志（plan 09）隐私边界。
6. **不打击信心（产品红线）**：避免向用户直接呈现「你从 B1 掉到 A2」式判决。优先展示**成长与覆盖**而非降级结论；面向用户的「水平变化」展示应克制或 opt-in，内部难度调节可先于公开标签生效。**§7.2 的「自适应为主角、明确等级降为配角」方向正是对这条红线的产品级解法**——淡化标签即消解降级判决。
7. **若自适应作为对外卖点 → 触及产品定位 / 主参考**：见 §7.2，需回写 `product-main-reference.md` 与入口文档，且承诺必须有真实能力支撑。

## 9. 复用 vs 新增工作

### 9.1 高复用 / 已有
- `memory_candidates`（difficulty / kind / 错误模式）已落库——核心信号现成。
- 句子分析 grammarNotes / keyPoints。
- `LanguageLevel` 枚举与 `ExplanationLanguageMode.derive` 的 level→体验映射框架。
- Apple `NaturalLanguage`（语种判定 + 文本复杂度），与语伴 §3.5 共用。
- Provider 抽象 + 请求预览 / 日志（plan 09）供方案 B 复用。

### 9.2 真实新增
- **Core 模型 `ProficiencyProfile`**（按空间）：总体 band + 置信度、分技能估计、知识覆盖摘要、趋势、`lastAssessedAt`、证据计数、来源标记。
- **GRDB schema**：画像表 + 可选评估历史表（用于趋势 / 进步可见）；local-only、默认不同步、可重建、可删除。
- **`ProficiencyAssessmentService`**：本地启发式聚合 + （可选）AI 校准 seam；定义触发节奏与阈值。
- **下游接线**：把 `ExplanationLanguageMode.derive`、材料生成难度、练习选材、复习排序从「静态 level」切到「评估后水平」（需兼容与回归）。
- **设置 UI**：手动重估、自评与评估关系展示、AI 校准开关（默认关闭）、进步 / 覆盖的克制呈现。
- **「水平总览 / 学习画像」专属页面（§7.1）**：三端入口 + 总体 / 分技能 / 常犯错误盲点 / 覆盖 / 趋势呈现 + 「看见问题→立即练」行动闭环；UI 工作量大头。
- **目标语种判定**：判断哪些记录是目标语书写，才能作为产出信号。

## 10. 大致实施路线（建议分期，待拆为正式 plan）

> 方向性路线，非承诺；正式拆解时按依赖排序，各自走 plan + 自审核 + 用户确认。

- **第 0 步（定位）**：ADR 细化决策 #6（自评=种子、画像=演进值、二者关系）；更新产品主参考与相关 spec。
- **第 1 步（MVP，纯本地、内部信号）**：
  - `ProficiencyProfile` Core 模型 + GRDB schema（local-only、可重建、可删除）。
  - 本地启发式：聚合 `memory_candidates` 难度分布 + 目标语记录复杂度 → **总体 band 估计 + 置信度**。
  - 先**内部消费**：接入材料生成难度 + `ExplanationLanguageMode`（保留向后兼容与回归）。
  - 触发：持续累积 + 累计阈值；设置中「重新评估」。
- **第 2 步（增量）**：分技能（理解 vs 产出）；**「水平总览 / 学习画像」页面（§7.1）**——先做总体水平 + 常犯错误 / 盲点清单 + 基础趋势；接入练习评分（待评分能力落地）。
- **第 3 步（增量）**：方案 B AI 校准（默认关闭、显式触发、最小发送、走 plan 09 预览 / 日志）。
- **第 4 步（远期）**：接入「语伴」对话输入作为产出证据；向量化覆盖分析。

## 11. 依赖与排序提示

- **建议排在「语伴」之前**（语伴难度自适应依赖本能力的水平信号）。
