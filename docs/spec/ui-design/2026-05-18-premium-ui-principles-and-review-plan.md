## 1. 目的

本规格用于把“页面不够美观、高级，不具备付费 App 级别设计感”转化为可执行的设计原则和审查流程。

它解决三个问题：

- 让后续 AI 不再凭“美化”这种模糊指令直接改页面。
- 让 LangoTrace 的视觉优化服务产品定位，而不是堆叠装饰效果。
- 在正式改 SwiftUI 代码前，先用统一标准完成三端 UI 全面审查和优化方案。

本规格不是完整品牌手册，也不是实现计划。它是后续 UI 审查、设计系统补强和页面样板重构的依据。

## 2. 产品定位对 UI 的要求

LangoTrace 是一款把真实生活变成语言学习材料的本地优先 Apple 三端付费 App。UI 必须让用户感到：

- 自己的生活记录正在形成长期语言资产。
- 当前语言空间、学习方向和能力边界清晰可信。
- 记录、转换、对照、练习和记忆是一个连续闭环。
- App 尊重隐私和本地数据，不用噱头抢主流程注意力。
- 这是可以长期每天打开的工具，而不是一次性体验 Demo。

因此，付费级设计感不等于更花哨。它来自更准确的信息层级、更稳的空间关系、更成熟的组件状态、更清楚的平台差异和更可信的细节完成度。

付费级 UI 的判断应同时覆盖四层：

- 产品层：是否强化“用生活记录学习语言”，而不是把 App 做成翻译器、聊天工具或课程目录。
- 交互层：用户是否能低摩擦完成记录、查看双语材料、进入练习和回到记忆来源。
- 系统层：三端是否尊重 Apple 平台习惯、状态边界、无障碍和本地化约束。
- 工程层：视觉语言是否沉淀为 token、组件、状态和验证流程，而不是散落在页面中的临时样式。

任何只改善截图但损害上述任一层的方案，都不能视为真正的付费级升级。

## 3. 设计原则

### 3.1 安静但不简陋

页面应保持低噪音和长期可读性，但不能像未完成的骨架。留白、边框、背景、分组和状态必须有明确用途。

可接受：

- 克制的中性色和少量语义强调色。
- 通过字体层级、间距和内容密度建立秩序。
- 使用系统材质或轻量面板表达层级。

不可接受：

- 大面积装饰性渐变、光斑、噪点或无语义背景。
- 只靠白底、灰线和静态文案撑起页面。
- 用大量卡片填补产品路径不清的问题。

### 3.2 个人语言资料库感

LangoTrace 的长期价值是把生活记录、双语表达、练习结果和词句记忆沉淀成个人资料库。UI 应强化“可积累、可回溯、可整理”的感觉。

设计要求：

- 时间线、记录详情、句子对照和记忆项之间要有可见来源关系。
- 词句、练习和 AI 生成内容应能回到原始生活记录。
- 列表项不只是标题列表，应表达记录类型、学习状态、来源和最近活动。

### 3.3 学习工具感优先于社交和游戏化

App 可以有温度，但不应像社区 feed、课程闯关或聊天机器人。

设计要求：

- 首页主动作围绕“今天记录一点生活”。
- 练习入口来自用户自己的内容，而不是外部课程关卡。
- 成长反馈可以轻量出现，但不使用强游戏化徽章、连续打卡压力或排行榜语境。

### 3.4 平台原生感高于跨端一致外观

iPhone、iPad 和 macOS 共享产品对象和设计语言，但不追求像素级一致。

设计要求：

- iPhone 聚焦单任务、快速记录、短练习和清晰返回路径。
- iPad 呈现沉浸式学习工作台，合理使用多栏、Inspector 和可收起辅助面板。
- macOS 呈现资料库和生产力工具，保留 Sidebar、Toolbar、Inspector、菜单栏和快捷键的扩展空间。

### 3.5 状态表达必须可信

当前项目仍处于真实数据、真实 AI、真实语音、真实同步和 StoreKit 之前。UI 必须准确表达 Mock、未配置、不可用和本地状态，不能制造已经完成真实能力的错觉。

设计要求：

- 未配置 AI Provider 是正常配置状态，不是错误。
- 同步未启用是正常状态，不使用危险或失败视觉。
- Local Mock 生成必须明确说明不会发送外部请求。
- 不可用页面需要说明当前边界、后续接入条件和不会发生的副作用。

### 3.6 设计系统服务产品对象

组件应优先表达产品对象，而不是抽象样式。

优先沉淀：

- `LanguageSpaceSwitcher`
- `EntryTimelineRow`
- `SentencePairView`
- `PracticeControlBar`
- `RequestPreviewCard`
- `MemoryItemRow`
- `PrivacyStatusPopover`
- `CapabilityStatusBadge`
- `UnavailableStateView`

不优先沉淀：

- 只表达视觉容器的通用大卡片。
- 与产品对象无关的装饰组件。
- 为单一页面临时创建的复杂样式。

### 3.7 本地化和可访问性是高级感的一部分

付费级 UI 不能只在默认语言、默认字号和理想屏幕尺寸下成立。

设计要求：

- 英文、简体中文和更长本地化文案都不能溢出或互相遮挡。
- 图标按钮必须有可访问 label、value 或 hint。
- iPhone 和 iPad 触控目标不小于 44pt。
- 状态不能只靠颜色表达。
- 动效必须尊重 Reduce Motion。

### 3.8 内容路径优先于界面装饰

每个主要页面都应能回答三个问题：

- 当前内容来自哪里。
- 用户下一步可以用它做什么学习动作。
- 这个动作会不会触发外部请求、权限、同步或持久化。

如果页面只能展示漂亮容器，但不能解释 Entry、Rendering、Practice 和 Memory 的关系，它就没有达到 LangoTrace 的设计目标。

### 3.9 渐进披露优先于说明堆叠

LangoTrace 涉及 AI、隐私、同步、语言空间和学习状态，不能把所有说明一次性堆到主页面。

设计要求：

- 主流程只展示当前决策所需的信息。
- 请求预览、权限解释、Provider 状态和同步边界通过 sheet、popover、Inspector 或详情页渐进展示。
- 高级配置和诊断信息不抢占记录和学习主流程。
- 不使用长段说明文案弥补交互不清；如果必须解释很多，通常说明页面结构或状态表达需要重做。

### 3.10 设计系统必须有代码边界

设计原则最终必须能落到 SwiftUI 可维护结构中。

设计要求：

- 颜色、字体、间距、圆角、边框、阴影和状态视觉通过 `LangoTraceDesign` 或同等设计系统入口表达。
- 页面不得大量散落一次性 hex、opacity、corner radius、padding 和 shadow 魔法数。
- 共享内容组件只表达产品对象和状态，不承担平台外壳职责。
- iPhone、iPad、macOS 的根布局可以不同，但不能复制三套无关视觉系统。
- 视觉升级不能让 View 直接访问网络、Keychain、数据库、Provider 或同步服务。

### 3.11 商业感来自完成度，不来自购买暗示

当前 StoreKit 尚未接入。UI 可以朝付费 App 质量打磨，但不能提前出现会误导用户的订阅、购买、恢复购买或 Pro 能力表达。

设计要求：

- 付费级感知来自排版、交互、状态、平台原生和可靠边界。
- 未实现购买、恢复购买和授权状态前，不把相关入口做成真实可用能力。
- 后续接入 StoreKit 时，购买页、恢复购买、家庭共享和隐私标签应单独设计并验证。

## 4. 三端审查维度

### 4.1 iPhone

审查问题：

- 首页是否把“今天记录一点生活”作为第一主动作。
- 五个 Tab 是否各自有清楚职责，是否存在入口堆叠。
- 记录、详情、练习和记忆之间是否形成单列闭环。
- 主按钮是否位于易触达区域，触控目标是否充足。
- 页面是否有过多解释文案，导致不像日常工具。
- 空状态和未配置状态是否可信且不打断主流程。
- iPhone SE 宽度、较大 Dynamic Type、横向输入和键盘弹起时，主操作是否仍可见。
- sheet、full-screen cover、NavigationStack 返回和系统边缘返回手势是否符合 iOS 习惯。
- 录音、拍照、照片、AI 生成等入口未接入时，是否明确不会触发权限或外部请求。

付费级目标：

- 像一个每天可以快速打开的小型记录学习工具。
- 少入口、强主线、清楚反馈。
- 能在短时间内完成记录、查看双语表达和进入一次练习。

### 4.2 iPad

审查问题：

- 三栏结构是否真正服务“时间线 / 主记录 / 学习面板”。
- 中间主区是否有足够视觉焦点，是否被左右面板抢注意力。
- 左右面板收起后是否进入更安静的专注状态。
- 筛选、时间线、句子解释和练习入口是否有明确层级。
- Split View、Slide Over 和 Stage Manager 窄窗口下是否仍可读。
- 触控、指针和键盘入口是否互相补充。
- Apple Pencil、硬件键盘、指针 hover 和触控是否不会互相冲突。
- 边缘手势是否避开系统手势，并始终有可见按钮替代。
- 多窗口或 Stage Manager 尺寸变化时，选中记录、滚动位置和面板状态是否稳定。

付费级目标：

- 像一个沉浸式语言学习工作台。
- 能同时看到生活记录、目标语言表达、逐句学习和练习入口。
- 多栏不是为了显得复杂，而是减少上下文切换。

### 4.3 macOS

审查问题：

- Sidebar、Toolbar、主区和 Inspector 是否承担不同职责。
- 视觉密度是否比 iPad 更接近资料库和生产力工具。
- 主区是否支持可阅读、可编辑、可整理的长内容体验。
- Inspector 是否表达请求预览、词句提取、元数据和练习状态，而不是静态说明。
- 菜单栏、快捷键、搜索和多窗口是否有清晰后续边界。
- 窗口缩放时是否保持可用，是否避免移动端布局放大。
- Settings、菜单栏和工具栏命令是否不会与 Sidebar 底部设置入口语义冲突。
- 右键菜单、键盘焦点、文本选择、复制和查找是否符合 Mac 用户预期。
- 最小窗口尺寸下是否优先保留主内容，而不是保留装饰和低频面板。

付费级目标：

- 像一个 Mac 原生个人语言资料库。
- 更重视管理、搜索、批量整理和长内容编辑。
- 视觉克制但信息组织更强。

## 5. 全项目 UI 审查流程

### 5.1 审查前读取

每次开始 UI 全面审查前必须读取：

- `AGENTS.md`
- `docs/product-main-reference.md`
- `docs/spec/002-navigation-and-routing.md`
- `docs/spec/003-ui-design-system.md`
- `docs/spec/006-interface-localization-and-language-boundaries.md`
- 本规格文档

根据代码范围继续读取：

- `Packages/LangoTraceUI/Sources/LangoTraceUI/`
- `LangoTraceApp/`
- 与页面状态相关的 Core / Data preview model

### 5.2 审查方法

按“产品路径 -> 平台结构 -> 视觉系统 -> 组件状态 -> 可访问性与本地化 -> 实现风险”的顺序检查。

审查必须先区分问题类型，避免把所有问题都归为“视觉不高级”：

- 产品路径问题：用户不知道为什么来到这里、下一步做什么或如何回到来源。
- 平台交互问题：导航、手势、窗口、键盘、指针或系统控件不符合对应平台习惯。
- 视觉系统问题：token、层级、密度、色彩、字体、圆角、阴影或状态不一致。
- 组件状态问题：普通、选中、禁用、不可用、加载、错误、空状态或完成状态缺失。
- 能力边界问题：Mock、Disabled、未配置、未实现或真实能力表达混淆。
- 工程结构问题：样式散落、平台外壳和共享内容耦合、View 承担服务或业务副作用。

每个问题必须记录：

- 平台：iPhone、iPad、macOS 或 shared。
- 页面或组件。
- 问题描述。
- 违反的设计原则或规范。
- 代码或文档证据。
- 严重度：P0、P1、P2、P3。
- 建议修复方向。
- 是否需要先更新规范或 worklog。
- 建议验证方式：单元测试、构建、模拟器截图、无障碍检查、本地化检查或手动路径验证。

严重度定义：

- P0：会误导真实能力、破坏隐私边界、导致主流程不可用或明显违反平台交互底线。
- P1：显著影响付费级感知质量、主视觉层级或核心学习闭环。
- P2：影响一致性、可读性、状态表达或平台细节，但不阻断主流程。
- P3：局部润色、微交互、文案密度或后续 polish。

审查时应优先处理 P0 和 P1。P2 和 P3 可以进入分批 polish，但不能阻塞核心闭环判断。

### 5.3 架构审查补充

从系统架构师角度，UI 审查还必须检查：

- `LangoTraceDesign` 是否足以承载新增视觉语言，还是需要先扩展 token。
- 新组件是否按产品对象拆分，是否能在 iPhone、iPad 和 macOS 之间复用内容而保留平台外壳差异。
- 页面状态是否明确属于 App-level、Feature-level 或 transient UI state。
- 选中项、筛选、面板展开、sheet、popover 和 inspector 内容是否没有误入 Core 模型、数据库或同步边界。
- Mock / InMemory 数据是否能被真实 Repository、AI、Speech、Sync 实现替换。
- 视觉升级是否引入不可测试的隐式状态、长生命周期异步任务或 View 内服务调用。
- 是否需要新增纯函数 helper 或轻量状态模型，使 route、filter、panel、capability state 可单元测试。

### 5.4 交互设计审查补充

从专业 iOS / iPadOS / macOS 交互设计角度，UI 审查还必须检查：

- 主要动作是否有明确视觉优先级，每屏不应出现多个同权重主按钮。
- 重要操作是否有反馈，异步或 mock 操作是否有明确 loading、完成、失败或不可用状态。
- 危险或不可恢复操作是否有确认、撤销或恢复路径。
- 手势是否只是加速路径，不是唯一入口。
- 触控目标、指针 hover、键盘焦点、VoiceOver 朗读顺序和 Dynamic Type 是否同时成立。
- 长内容编辑、句子对照、练习控制和请求预览是否能在输入法、键盘和窗口尺寸变化下保持稳定。
- 空状态是否提供下一步动作，而不是解释产品愿景。

### 5.5 审查产物

全面审查完成后应产出：

- 一份 `docs/plans/done/YYYY-MM-DD-feature-premium-ui-audit.md` 或同主题 worklog。
- 一份问题清单，按平台和严重度排序。
- 一份优化方案，明确样板页面、设计系统改动、实施批次和验证方式。
- 如发现 Accepted guideline 已经不足，应提出对 `docs/spec/003-ui-design-system.md` 的定向修改建议。
- 一份样板页面候选清单，说明为什么选它、覆盖哪些产品对象、能沉淀哪些 token 和组件。
- 一份风险清单，列出可能误导真实能力、破坏隐私边界、过度重写或增加架构债务的方案。

### 5.6 不允许的审查结论

不接受以下结论：

- “整体不够高级，需要美化。”
- “加渐变、加阴影、加动画。”
- “参考某个 App 全量重做。”
- “三端统一改成同一种卡片风格。”
- “先直接改代码，改完再看。”

所有结论必须能回到产品定位、平台规范、现有代码证据和可验证优化路径。

## 6. 后续优化方案结构

全面审查后的优化方案应按以下结构组织：

### 6.1 第一阶段：设计系统底座

目标：

- 补强 `LangoTraceDesign` 的语义 token。
- 建立核心组件状态。
- 统一 empty、unavailable、local mock、provider disabled、sync disabled 的表达方式。
- 明确浅色、深色、Reduce Transparency 和高对比度下的设计边界。
- 建立状态组件的文案、图标、颜色和可访问性模式。

验收：

- 页面中高频颜色、间距、圆角、状态视觉不再散落为魔法数。
- 核心状态在三端有一致语义和平台适配。
- 本地化长文案和 Dynamic Type 不造成明显遮挡。
- 未配置、不可用和 Local Mock 不会被误读为真实 AI、同步、语音或购买能力。

### 6.2 第二阶段：三端样板页面

建议样板：

- iPhone：今日页和记录详情页。
- iPad：三栏学习桌面。
- macOS：主工作台和 Inspector。

目标：

- 用少量页面确定视觉语言和组件质量。
- 通过模拟器截图验证真实效果。
- 修正 token 和组件后再推广。
- 验证 Entry、Rendering、Practice、Memory 和 Capability State 至少各有一个真实承载位置。
- 验证 iPhone 单列、iPad 多栏和 macOS 工作台不是同一布局的机械放大。

### 6.3 第三阶段：页面推广

目标：

- 将样板页面沉淀的组件和状态推广到记录、练习、记忆、设置和 unavailable 页面。
- 保持平台差异，不做机械复制。

### 6.4 第四阶段：质量验证

目标：

- 使用 `scripts/verify.sh` 验证工程。
- 使用 iPhone、iPad 和 macOS 构建或截图验证主要页面。
- 检查本地化、Dynamic Type、Reduce Motion、深色模式边界和无障碍标签。

深色模式只有在 token 映射、截图检查和可读性检查完成后，才能写成已支持能力。

最低截图和手动验证矩阵：

- iPhone：小屏宽度、默认字号、较大 Dynamic Type、键盘弹起、至少英文和简体中文。
- iPad：regular width、Split View 窄宽度、左右面板分别收起、Stage Manager 窗口变化。
- macOS：默认窗口、最小可用窗口、Sidebar 收起、Inspector 收起、Settings 或能力详情页。
- 状态：empty、local mock、AI Provider 未配置、同步未启用、unavailable、request preview、error。
- 辅助能力：VoiceOver label 抽查、键盘焦点抽查、Reduce Motion、深色模式边界声明。

任何截图验证都必须回答：主行动是否可见、内容是否溢出、状态是否可信、平台形态是否正确、是否存在明显装饰替代产品路径的问题。

## 7. 边界问题清单

后续审查和优化时必须主动检查以下边界。

### 7.1 真实能力与 Mock 边界

- Local Mock 不得使用“已生成”“已同步”“已连接”等容易被理解为真实能力完成的文案。
- AI Provider 未配置时，请求预览仍可展示，但必须说明不会发送外部请求。
- TTS、录音、OCR、照片、同步、导出、StoreKit 未接入时，入口可以存在，但必须落到 unavailable、mock 或只读说明。
- 任何会触发权限弹窗的能力，正式接入前必须单独设计权限解释路径。

### 7.2 数据和隐私边界

- 日记、照片、音频、历史记忆和目标语言写作内容不能因为页面打开、列表滚动或预览展示而自动发送给 Provider。
- 请求预览要区分将发送、不会发送、只保存在本地和只作为 mock 展示的内容。
- 视觉优化不能隐藏隐私状态图标，也不能把 AI Provider 和同步合并成一个模糊状态。
- 长期记忆和相似记录如果参与 AI 上下文，必须有单独的范围表达和确认边界。

### 7.3 平台和尺寸边界

- iPhone 小屏、横屏、输入法和较大字号不能破坏主流程。
- iPad Slide Over、Split View 和 Stage Manager 窄窗口不能把主内容挤压到不可用。
- macOS 最小窗口不能只剩 Sidebar 或 Inspector；主内容优先级最高。
- 面板、Inspector 和 popover 的状态属于 transient UI state，除非另有设计，不进入同步或语言空间模型。

### 7.4 语言和本地化边界

- App 界面语言、用户母语、目标学习语言、Prompt 输出语言和 TTS/OCR 语言必须分层。
- UI 文案不能为了展示英语学习示例而强行变成英语。
- 语言选择、空间名称和学习等级应使用稳定 code 与本地化显示分离。
- 进入多语言界面支持后，核心路径必须检查长文本、CJK 断行、RTL 或伪本地化 smoke。

### 7.5 设计债务边界

- 不用“先美化后整理”作为理由增加临时样式扩散。
- 不在一个大 View 中堆叠三端平台差异。
- 不为一个页面创建只能使用一次的复杂视觉抽象。
- 不通过全局状态或事件总线解决局部 UI 问题。
- 不为了截图效果提前宣称深色模式、同步、AI、语音、购买或导出已经完成。

## 9. 完成标准

这份规格本身的完成标准：

- 能清楚解释 LangoTrace 的付费级 UI 不等于装饰性美化。
- 能指导后续 AI 做代码级、平台级、规范级 UI 审查。
- 能把审查问题转化为分阶段优化方案。
- 不与现有产品定位、导航规范、UI 规范和本地优先决策冲突。

后续 UI 优化的完成标准：

- 三端至少各有一个样板页面达到新规范要求。
- 设计 token、核心组件和状态模式能支撑页面推广。
- 主要页面经过模拟器或本机截图验证。
- 文档、代码和验证记录保持同步。
- 后续实现没有引入真实能力误导、平台交互倒退、服务边界穿透或样式债务扩散。
