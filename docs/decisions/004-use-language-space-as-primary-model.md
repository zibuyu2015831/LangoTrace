# ADR-004: 采用语言空间作为核心信息模型

日期：2026-05-17

状态：Accepted

## 背景

语迹 LangoTrace 支持用户长期学习多种目标语言。用户可能同时学习英语、日语、法语等语言，也可能在同一门语言中记录生活、工作、旅行、会议、情绪和照片故事。

如果没有清晰的信息模型，后续会出现以下问题：

- 多语种记录、词句、练习、Prompt、TTS 声音和学习报告混在一起。
- 用户初次使用时需要理解 Project、目录或工作区等抽象概念。
- 工作和生活分类会增加随手记录的心理负担。
- 同步、复习、统计和长期记忆难以建立稳定边界。

## 决策

采用“语言空间”作为语迹第一版的核心信息模型。

一个语言空间对应一门目标语言的长期学习档案，例如：

```text
英语空间
日语空间
法语空间
```

首次启动不默认创建语言空间，而是先询问并记录：

```text
母语
目标语言
水平自评
```

用户确认后，系统再创建第一个语言空间。

工作、生活、旅行、会议、邮件、情绪等不作为顶层空间，而作为标签、场景、Prompt 模式或筛选条件。

第一版不使用 Project 作为面向用户的核心概念，也不支持多用户、家庭或教师学生管理。

## 备选方案

### 方案 A：单一总空间

所有语言、记录和练习都放入一个总空间。

优点：

- 初始结构最简单。
- 时间线天然连续。

缺点：

- 多目标语言的词句、错误模式、TTS 声音、Prompt 和复习队列会混杂。
- 长期成长报告难以按语种呈现。
- 同步和导出边界不清晰。

### 方案 B：Project 模型

使用 Project 表达不同学习资料、工作场景或生活主题。

优点：

- 对知识管理类工具熟悉。
- 适合专业资料库和批量管理。

缺点：

- 不符合多数语言学习者的第一心智。
- 初次使用门槛更高。
- 容易让语迹显得像项目管理工具，而不是生活驱动的语言学习 App。

### 方案 C：按工作和生活拆分空间

把工作、生活、旅行等场景设为顶层空间。

优点：

- 看起来贴近实际场景。
- 某些用户可能希望区分职场和个人内容。

缺点：

- 真实记录经常跨场景，用户需要额外分类。
- 会削弱“随手记录”的轻量体验。
- 同一门语言的学习资产被拆散，不利于复习和长期记忆。

### 方案 D：语言空间模型

按目标语言建立学习空间，场景作为标签或模式。

优点：

- 符合“我的英语、我的日语”的学习心智。
- 便于隔离词典、TTS、Prompt、复习队列、错误模式和成长报告。
- 支持多语种学习，同时保持信息架构简单。
- 与本地优先、单人使用和买断制定位一致。

缺点：

- 同一天跨多个目标语言学习时，需要切换空间。
- 某些跨语种对比学习能力需要后续单独设计。

## 影响

- 数据模型应以 Language Space 作为关键聚合边界。
- Entry、Prompt Preset 偏好、TTS 声音、词句记忆、练习记录、错误模式和成长报告默认归属于某个语言空间。
- iPhone 顶部或首页需要显示轻量语言空间切换器。
- iPad 和 macOS 顶部工作区需要常驻但低干扰的语言空间切换入口。
- 左侧 Sidebar 不应重复堆叠多个语言空间卡片。
- “工作”“生活”“旅行”等概念应实现为标签、场景或 Prompt 模式。

## 风险

- 如果用户把语迹当作通用日记工具，可能期待跨语言连续时间线。
- 如果用户同时学习多门语言，切换入口的设计质量会影响体验。
- 如果未来加入教学或团队场景，单人语言空间模型需要扩展。

缓解方式：

- 保留全局时间线或全局搜索的可能性，但不要在第一版把它作为主结构。
- 语言空间切换使用轻量 pill 或菜单，不做重型 Project 管理。
- 在设置中提供添加学习语言，而不是把多语言空间作为初次使用负担。

## 复审条件

以下情况需要复审本决策：

- 早期付费用户明确把语迹当作通用多语言日记，而不是按目标语言学习。
- 工作/生活强隔离成为高频刚需。
- 多用户、教学或团队协作成为产品主方向。
- 跨语种对比学习成为核心卖点，需要重新设计空间边界。
