# ADR-005: 坚持本地优先和用户自带 Provider

日期：2026-05-17

状态：Accepted

## 背景

语迹 LangoTrace 处理的数据高度私人化，包括日记、照片、语音、目标语言写作、错误模式、学习记录、Prompt Preset、词句记忆和长期语言成长轨迹。

产品定位是买断制收费 App，并强调用户掌控数据。AI 请求、Embedding、TTS、OCR、对象存储同步等能力如果直接绑定官方云服务，会带来隐私、成本、地区可用性、长期锁定和商业模式复杂度。

## 决策

语迹第一版坚持本地优先和用户自带 Provider。

具体原则：

- 主数据默认保存在 App 私有容器。
- 首次启动不要求选择目录。
- AI 功能默认不自动启用，需要用户配置 Provider 或明确触发。
- AI、Embedding、TTS、OCR、图片理解、语音识别通过 Provider 抽象接入。
- 支持 OpenAI-compatible base URL、模型名、API Key 和必要请求配置。
- API Key 默认保存到 Keychain。
- API Key、对象存储密钥和加密密钥默认不同步。
- 照片、日记、音频和历史记忆只有在用户明确触发相关能力时才发送给 Provider。
- 同步采用 Sync Engine + Adapter 思路，iCloud / WebDAV / S3 / R2 等作为适配器，不绑定 CloudKit-only。
- FTS、向量索引和缓存属于可重建派生数据，默认不作为同步主数据。

**补充说明（2026-06-15）**：本 ADR 的"数据本地化"原则不禁止在本地对用户数据做分析处理。App 在本地积累语言能力（Ability）、生活记忆（Memory）和表达风格（Style），是产品必须的本地能力，分析结果留在 App 容器内，不离开设备，不违反本 ADR 的本地优先原则。真正受本 ADR 约束的是两类外发行为：**a) 用户主动发起的 AI 交互**（打字发消息、点击触发生成等）本身即构成明示触发；**b) 系统自动注入给 Provider 的数据**（如 Memory 生活事实、Style 摘要），必须明示授权或提供关闭选项（受核心决策 #10 约束）。结构化 PII（手机号、身份证号）在外发前做确定性 scrubbing 作为 defense-in-depth 补充。另一条边界是本地静态安全（FileProtection、Keychain）。本地分析本身不在本 ADR 的禁止范围内。

## 备选方案

### 方案 A：官方云服务优先

App 默认提供官方 AI、官方账号和官方同步。

优点：

- 新用户开箱即用。
- 产品体验更可控。
- 更容易统一模型、日志和同步体验。

缺点：

- 与本地优先和用户掌控数据的定位冲突。
- 服务成本、地区合规和隐私责任显著提高。
- 买断制商业模型会被持续 AI 和同步成本稀释。

### 方案 B：CloudKit-only

只支持 Apple 生态内 CloudKit 同步。

优点：

- Apple 用户体验自然。
- 开发路径比自定义对象存储更短。

缺点：

- 与用户自定义对象存储的产品设想冲突。
- 难以支持 WebDAV / S3 / R2 等用户自有方案。
- 长期同步协议边界容易被 CloudKit 模型绑定。

### 方案 C：本地优先 + 用户自带 Provider

App 提供本地数据能力、Provider 抽象、请求预览和自定义同步适配器。

优点：

- 符合隐私和买断制定位。
- 用户可选择自己的 AI、Embedding、TTS、OCR 和存储服务。
- 降低官方持续服务成本和平台锁定。
- 有利于高级用户长期掌控自己的语言资产。

缺点：

- 初次配置门槛更高。
- 错误处理和 Provider 兼容性更复杂。
- 需要更清晰的设置、请求预览和故障诊断体验。

## 影响

- 工程上必须有 Provider 层，页面不能直接调用具体 AI 服务。
- 设置中需要清晰管理 AI Provider、对象存储、同步状态、请求预览和密钥状态。
- 数据模型必须区分主数据、派生数据、缓存和可重建索引。
- 同步协议必须避免默认同步密钥和本地派生索引。
- 产品文案需要把“本地优先”和“用户掌控数据”讲清楚，但不要把首次体验变成配置流程。

## 风险

- 普通用户可能不理解 API Key、base URL 和对象存储。
- 不同 Provider 的模型能力、返回格式和限制不一致。
- 用户自定义对象存储会带来凭证、费用、可用性和冲突处理问题。
- 如果没有官方默认 Provider，新用户可能无法立即体验 AI 转换价值。

缓解方式：

- 首次启动先进入记录闭环，AI Provider 可稍后配置。
- 设置中提供 OpenAI-compatible 模板和请求预览。
- 对普通用户隐藏高级请求头、模型参数和同步细节。
- 后续可以评估官方托管 Provider 或推荐配置，但不能破坏本地优先边界。

## 复审条件

以下情况需要复审本决策：

- 市场验证显示大多数付费用户强烈需要官方开箱即用 AI。
- App Store 审核、地区合规或模型供应导致自定义 Provider 体验不可控。
- 自定义对象存储同步的维护成本显著高于商业收益。
- 产品商业模式从买断制转向订阅或官方云服务。
