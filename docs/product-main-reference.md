# 语迹 / LangoTrace 产品主参考文档

## 1. 产品名称

中文名：语迹

英文名：LangoTrace

名称含义：

- “语”代表语言、表达、学习目标和多语种能力。
- “迹”代表生活痕迹、记录、成长轨迹和长期积累。
- LangoTrace 对应 “language + trace”，强调用日常记录沉淀个人语言学习轨迹。

这个名称不直接解释具体功能，因此需要稳定搭配主 slogan 和副标题使用。

## 2. 主 Slogan

中文主 slogan：

> 用生活记录学习语言。

英文主 slogan：

> Learn languages from your life.

这两句作为产品长期核心表达，不建议频繁更换。它们的作用是让用户第一时间理解：语迹不是传统背单词 App，也不是 AI 聊天工具，而是把自己的真实生活转化为语言学习材料的工具。

## 3. 产品定位

语迹 / LangoTrace 是一款支持 MacBook、iPad、iPhone 三端的收费语言学习 App，面向所有语种学习者，不局限于英语。

它不是 AI 聊天工具，也不是传统课程或背单词 App，而是一个“用生活记录学习语言”的本地优先学习工具。

用户用自己的母语记录日常生活、工作、旅行、心情、想法、照片和片段。AI 将这些熟悉的内容转换成目标语言，并通过文本转语音、逐句对照、跟读、听写、回译、词句收藏和复习等方式，帮助用户从自己的真实生活材料中自然学习外语。

核心定位一句话：

> 语迹是一款把你的真实生活变成外语学习材料的本地优先语言学习 App。

英文定位一句话：

> LangoTrace turns your real life into personal language-learning material.

## 4. 核心理念

语迹的核心理念是：语言学习不应只依赖陌生课文、标准教材或孤立单词，而应尽可能从用户真实、熟悉、有情绪关联的生活内容出发。

用户每天真实发生的事、拍下的照片、想到的一句话、工作中的表达需求、旅行中的见闻、情绪和记忆，都可以成为可理解、可朗读、可跟读、可听写、可复习的语言学习材料。

语迹的长期目标不是让用户完成一套课程，而是帮助用户沉淀自己的多语言生活记录、常用表达、词汇、句子、照片和语言成长轨迹。

## 5. 产品差异化

语迹与常见语言学习 App 的区别：

- 不是 AI 聊天，而是写作记录和语言训练工具。
- 不是学习陌生材料，而是把用户自己的生活变成学习材料。
- 不是只学单词，而是学习真实语境中的表达。
- 不是课程驱动，而是生活驱动。
- 不是云端账号和平台绑定优先，而是本地优先、用户掌控数据。
- 不是单次翻译工具，而是长期沉淀个人语言记忆系统。

与常见产品的对比：

- Duolingo 更偏游戏化课程和练习关卡；语迹更偏个人生活语料和真实表达。
- Babbel / Busuu 更偏结构化课程、对话和复习；语迹更偏用户自有内容。
- ELSA Speak 更偏英语发音训练；语迹面向多语种，并覆盖写作、听力、跟读、听写、回译和词句积累。
- LingQ / Readlang 更偏阅读外部内容；语迹更强调用户自己的日记、照片和生活片段。
- Anki / Mochi 更偏卡片复习；语迹的复习内容来自完整生活上下文。
- AI 对话类产品更偏角色扮演和聊天；语迹应避免被理解成聊天机器人。

## 6. 目标用户

主要用户：

- 正在学习任意外语的人。
- 想提升口语、听力、写作表达的人。
- 喜欢写日记、记录生活、整理照片的人。
- 希望用真实生活内容学习语言的人。
- 注重隐私、本地数据和数据可控的人。
- 愿意为高质量、设计感强、长期使用的工具付费的人。
- 不满足于刷题、背词或 AI 陪聊，希望建立个人语言资产的人。

典型使用动机：

- “我想知道自己日常生活里的这些话，用目标语言应该怎么自然表达。”
- “我想用跟自己有关的内容练听力和口语。”
- “我不想每天打开一个陌生课程，而是想把生活本身变成学习材料。”
- “我希望学习数据保存在本地，不被平台锁死。”
- “我希望长期积累自己的双语生活记录和表达库。”

## 7. 核心学习闭环

语迹的核心体验应围绕一个清晰闭环展开：

1. 记录：用户用母语写下生活、想法、情绪、工作片段、旅行经历或照片故事。
2. 转换：AI 将内容转换为目标语言，生成自然、地道、适合学习的表达。
3. 对照：母语与目标语言逐句对齐，帮助用户理解“我想说的话在目标语言中如何表达”。
4. 听说：生成目标语言音频，用户可以朗读、跟读、影子跟读、模仿和背诵。
5. 输出：用户进行听写、回译、复述和自测。
6. 提取：系统提取值得学习的单词、短语、句型和整句表达。
7. 复习：词句进入复习系统，并能回到原始生活上下文。
8. 沉淀：长期形成用户自己的双语生活档案、表达库、照片记忆和语言成长轨迹。

产品首页应尽量围绕一个主动作展开：

> 今天记录一点生活。

练习、复习和长期记忆都应从这个主动作自然延伸出来。

语迹还应支持一条面向中高级用户的自主写作闭环：

1. 自主写作：用户直接用目标语言记录生活、想法或文章。
2. 录入：用户可以键盘输入，也可以拍照录入手写文章。
3. 识别：系统通过 OCR 或 AI 识别图片中的手写文本，用户可校对识别结果。
4. 检测：AI 检测拼写、语法、搭配、语序、用词和标点问题。
5. 修改：AI 提供最小修改版、自然表达版或风格改写版。
6. 讲解：系统逐句解释修改原因和可替代表达。
7. 沉淀：错误模式、改正后的句子和高价值表达进入长期学习记忆。

这条闭环的产品意义是：用户先通过母语记录学习目标语言表达，随着能力提升，再逐渐直接用目标语言记录自己的生活。

## 8. 数据空间、初次使用与信息架构决策

语迹第一版应采用“多语言空间，但首次引导创建第一个空间”的产品设计。

推荐产品表达：

> 一个语言空间，就是一门目标语言的长期学习档案。

原因：

- 语言学习的用户心智通常按目标语种组织：我的英语、我的日语、我的法语。
- 每种目标语言的词句、错误模式、Prompt Preset、TTS 声音、词典、学习等级、复习队列和成长报告都不同。
- 如果把英语和日语混在同一个学习空间里，复习、统计和长期记忆会变得不够清晰。
- 如果把工作/生活拆成空间，用户会产生分类压力；但如果按语种拆分，用户几乎不用思考。

第一版 UI 不应使用“Project”作为核心概念。更适合的词是：

- 语言空间。
- 英语空间。
- 日语空间。
- 资料库。
- 语言记忆。

首次启动不应默认创建语言空间，而应先询问并记录用户的基础学习信息：

```text
母语：中文
目标语言：英语
水平自评：B1
```

用户确认后，系统再基于这些信息创建第一个语言空间，例如“英语空间”。

用户之后可以添加新的学习语言，例如：

```text
英语空间
日语空间
法语空间
```

每个语言空间都对应一个目标语言，并拥有相对独立的：

- 学习等级。
- 记录时间线。
- AI 生成历史。
- Prompt Preset 偏好。
- TTS 声音设置。
- 词典与 OCR 偏好。
- 词句记忆。
- 错误模式。
- 复习队列。
- 成长报告。
- 同步状态。

### 8.1 不按工作和生活拆分空间

第一版不建议区分“工作空间”和“生活空间”。

工作、生活、旅行、情绪、会议、邮件、社交媒体等更适合作为：

- 标签。
- 场景。
- 记录分类。
- Prompt 模式。
- 生成风格。
- 复习筛选条件。

原因：

- 一条真实记录可能同时包含工作和情绪，很难稳定归类到某个空间。
- 工作/生活拆分会削弱“随手记录”的轻量体验。
- 语迹的核心不是项目管理，而是围绕某门语言建立长期表达能力。

推荐原则：

> 语种是空间，场景是标签。

例如在“英语空间”中，可以有日常生活、工作表达、旅行、情绪、会议、邮件等标签。

### 8.2 单人使用与买断制

语迹第一版应明确为单人使用的个人语言学习 App，不建议支持多用户、家庭成员或教师/学生管理。

原因：

- 日记、照片、AI 请求、错误模式和发音练习都高度私人化。
- 单人使用更符合本地优先和隐私承诺。
- 单人授权也更符合买断制商业模式，有利于推广和销售转化。
- 多用户会引入账号权限、数据隔离、云端协作、家庭共享和教学管理等复杂方向，偏离第一版精品买断 App。

推荐产品表达：

> 每个购买用户管理自己的语言空间。

### 8.3 首次使用不要求选择目录

首次启动不应要求用户选择数据目录。

推荐首次路径：

1. 选择母语。
2. 选择正在学习的目标语言。
3. 选择学习水平。
4. 用户确认后，创建第一个语言空间，例如“英语空间”。
5. 选择是否现在配置 AI Provider。
6. 进入“今天记录一点生活”。

首次体验只需要安静提示：

> 数据默认保存在本机。你可以稍后在设置中配置 AI、备份和同步。

目录选择、对象存储、自定义同步和完整备份应放在设置或 Mac 高级工作台中，而不是初次使用门槛。

原因：

- iPhone / iPad 上选择目录不符合普通 App 心智。
- 收费 App 的第一体验应尽快进入记录和学习闭环。
- 过早要求选择目录会让用户担心选错位置、丢失数据或无法同步。
- App Sandbox、iCloud Drive、对象存储和本地数据库权限都不适合作为第一屏问题。

### 8.4 一级导航不使用“我的”

语迹不建议把“我的”作为核心一级菜单。

“我的”容易让产品显得像账号中心、内容社区或普通工具 App。语迹强调本地优先、买断制和个人语言资产，因此更适合直接呈现功能对象。

iPhone 底部 Tab 推荐为：

```text
今日 / 记录 / 练习 / 记忆 / 设置
```

其中：

- 今日：最高频入口，承载“今天记录一点生活”。
- 记录：日记、照片、手写录入和目标语言写作。
- 练习：朗读、跟读、听写、回译和复述。
- 记忆：单词、短语、整句、相似记忆、错误模式和复习。
- 设置：AI Provider、同步、隐私、购买恢复、导入导出和数据空间。

“单词”不建议作为底部一级菜单名称。语迹不是传统背单词 App，`记忆` 更能覆盖单词本、短语本、句子本、生活上下文和长期语言记忆系统。

在 iPhone 顶部或首页应有轻量语言空间切换器，例如：

```text
英语 · B1  v
```

点击后显示：

```text
英语
日语
法语
添加学习语言
```

这比 Project 切换更符合语言学习心智。

iPad 和 MacBook 也应有常驻但轻量的语言空间切换入口。推荐放在工作区顶部，使用 pill 形态：

```text
英语空间 · B1  v
```

设置入口应稳定可达，但不应抢占学习主流程。iPad 和 MacBook 推荐使用右上角齿轮图标或系统菜单中的 Settings，而不是把“设置”做成与记录、练习、记忆平级的大 Tab。

推荐原则：

- 语言空间切换是当前上下文，应常驻可见。
- 设置是系统配置，应低干扰可达。
- 顶部只保留少量全局元素，例如语言空间、搜索/命令、本地保存状态和设置图标。
- 左侧 Sidebar 不应重复堆叠多个语言空间卡片，避免页面显得像后台管理系统。

## 9. 核心功能设想

### 9.1 日常写作记录

用户可以像写日记一样，用母语记录生活、工作、旅行、心情、想法、对话片段、灵感和学习需求。

记录形式包括：

- 短句记录。
- 长篇日记。
- 工作或学习片段。
- 情绪记录。
- 旅行记录。
- 照片故事。
- 想用目标语言表达的一句话。

### 9.2 AI 转换目标语言

AI 将用户的母语记录转换成正在学习的目标语言。

建议支持多种生成模式：

- 自然表达版。
- 简单入门版。
- 更地道版。
- 口语版。
- 正式书面版。
- 社交媒体版。
- 旅行场景版。
- 职场场景版。

这些生成模式在技术实现上可以理解为不同的 Prompt Preset。每个 preset 由默认 system prompt、输出格式约束、学习目标和可选参数组成。普通用户看到的是“生成风格”或“学习模式”，高级用户可以进一步查看、复制和自定义 prompt。

同一条记录可以在当前语言空间内生成多个学习版本，方便不同水平和不同场景的用户学习。

### 9.3 AI 生成模式与 Prompt Preset 系统

AI 文本转换能力应设计成一个可扩展的 Prompt Preset 系统，而不是把所有生成逻辑写死在单一提示词中。

默认情况下，语迹应内置一组官方生成模式，让普通用户无需理解 prompt 工程也能直接使用。

建议内置模式：

- 自然表达版：将母语记录转换为自然、清晰、适合日常使用的目标语言。
- 简单入门版：使用更短句、更基础词汇，适合初学者理解和朗读。
- 更地道版：在保留原意的基础上生成更接近母语者习惯的表达。
- 口语表达版：偏向日常对话、轻松自然、适合跟读和复述。
- 正式书面版：适合邮件、工作、正式说明和书面表达。
- 社交媒体版：适合朋友圈、X、Instagram、小红书等短内容表达。
- 旅行场景版：适合旅行记录、问路、点餐、住宿、交通等场景。
- 职场场景版：适合会议、汇报、沟通、计划和专业表达。
- 逐句学习讲解版：输出逐句对照、关键词、短语、句型和可替代表达。
- 词句提取版：从生成内容中提取适合收藏和复习的单词、短语与整句表达。
- 目标语言写作检查版：检测用户直接用目标语言写作时的错误和不自然表达。
- 最小纠错版：尽量保留用户原句，只修正必要问题。
- 自然润色版：将用户的目标语言写作调整为更自然、更清晰的表达。
- 错误模式提取版：从用户写作和修改结果中提取反复出现的问题。

每个默认 Prompt Preset 应包含：

- 模式名称。
- 简短说明。
- system prompt。
- 适用目标语言。
- 适用学习水平。
- 输出格式要求。
- 是否启用逐句对照。
- 是否提取单词、短语和句子。
- 是否允许引用个人长期记忆。
- 是否适合生成音频和跟读材料。

高级用户应能够创建自己的生成模式。

自定义 Prompt Preset 可支持：

- 自定义名称和描述。
- 自定义 system prompt。
- 指定目标语言或语种范围。
- 指定学习水平，例如 A1-C2。
- 指定输出结构，例如 JSON、Markdown、逐句表格或纯文本。
- 指定是否调用长期记忆和向量检索上下文。
- 指定是否自动生成词句提取结果。
- 指定是否生成适合 TTS 的文本。
- 复制内置 preset 后修改。
- 导入和导出 preset 配置。

这个能力能让语迹适配不同学习目标。有人想练日常口语，有人想写工作邮件，有人想学旅行表达，有人想让输出更适合日语敬语、法语日常表达或德语书面表达。Prompt Preset 系统相当于把“语言转换规则”交给用户掌控。

产品界面上应避免让普通用户被 prompt 细节打扰。建议分层设计：

- 普通模式：用户选择“自然表达”“简单版”“口语版”等可理解选项。
- 高级模式：用户可以查看和编辑 prompt、输出格式和长期记忆调用方式。
- 专家模式：用户可以管理 preset 配置、导入导出、自定义变量和调试输出。

### 9.4 逐句对照与解释

语迹不应只提供整段翻译，而应尽量提供逐句学习结构。

每个句子可以包含：

- 母语原句。
- 目标语言句子。
- 关键词。
- 常用短语。
- 句型结构。
- 可替代表达。
- 使用场景说明。
- 学习难度标记。

这部分是语迹区别于普通翻译工具的重要能力。

### 9.5 朗读与跟读

系统为目标语言文本生成配音，用户可以听、跟读、模仿和背诵。

建议支持：

- 全文朗读。
- 逐句播放。
- 单句循环。
- 慢速播放。
- 原速播放。
- 跟读录音。
- 跟读对比。
- 影子跟读模式。

未来可以加入发音评分，但第一阶段不应让产品变成纯发音训练工具。

### 9.6 听写与回译

听写与回译是语迹的关键训练模式。

听写模式：

- 播放目标语言音频。
- 用户根据音频输入目标语言。
- 系统对比原文，标出遗漏、拼写、词形和语序问题。

回译模式：

- 显示目标语言句子。
- 用户尝试翻译回母语。
- 系统对照原始记录，帮助用户确认理解。

也可以提供反向训练：

- 显示母语原句。
- 用户尝试写出目标语言。
- 系统与 AI 生成版本进行对比。

### 9.7 照片引导写作

当用户不知道写什么时，可以拍一张照片或导入图片。AI 根据照片中的场景、物品、地点、情绪、人物关系或故事线索，帮助用户找到写作话题。

照片功能不应只做“图片描述”，而应成为写作启动器。

可生成的问题包括：

- 这张照片里发生了什么？
- 你为什么拍下这张照片？
- 这张照片让你想起了什么？
- 照片中的哪个物品值得描述？
- 如果用目标语言发朋友圈，可以怎么写？
- 如果给朋友讲这张照片，可以怎么说？
- 这张照片背后有什么故事？

### 9.8 自主写作模式：目标语言写作检测与修改

语迹应支持用户直接使用正在学习的目标语言写作，然后由 AI 进行检测、修改、讲解和沉淀。

这个功能不应被定位成通用作文批改或 Grammarly 式写作工具，而应服务于核心理念：

> 帮助用户直接用目标语言记录自己的生活，并理解自己与自然表达之间的差距。

AI 检测可以覆盖：

- 拼写。
- 语法。
- 词形。
- 介词。
- 搭配。
- 语序。
- 标点。
- 不自然表达。
- 不符合语境的用词。

AI 修改应提供多种层级：

- 最小修改版：尽量保留用户原句，只修正明显错误。
- 自然表达版：让表达更自然、更接近母语者习惯。
- 更地道版：在保留原意的基础上提高表达质量。
- 口语版：适合日常对话、跟读和复述。
- 正式版：适合邮件、工作、说明和书面表达。

逐句讲解应包含：

- 用户原句。
- 修改后句子。
- 修改原因。
- 可替代表达。
- 相关短语或句型。
- 是否建议收藏或复习。

自主写作模式应沉淀：

- 用户反复出现的错误。
- 用户已经掌握的表达。
- 修改后的高质量句子。
- 原句与修改句之间的差异。
- 适合复习的单词、短语和句型。

### 9.9 拍照录入手写文章

语迹应支持用户通过拍照录入手写目标语言文章，尤其适合 iPhone 和 iPad 场景。

这个功能的重点不是做通用扫描工具，而是把纸上的目标语言写作快速转成可检测、可修改、可复习的学习材料。

基本流程：

1. 用户拍摄手写文章。
2. 系统支持裁剪、旋转和增强对比度。
3. OCR 或 AI 识别手写文本。
4. 用户校对识别结果。
5. 识别文本作为一条目标语言 Entry 保存。
6. 进入 AI 写作检测、修改和讲解流程。
7. 原始图片与识别文本、修改版本和学习记忆关联。

优先级建议：

- 目标语言手写识别优先于母语手写识别。
- 第一阶段不承诺完美识别所有语种和所有笔迹。
- MVP+ 或 1.1 阶段可以支持“图片识别文本 + 用户校对 + AI 修改”。
- 第一版如需控制复杂度，可先支持图片附件和手动转写，后续再补强 OCR。

需要特别注意多语种手写识别质量差异，例如英文连笔、日语、韩语、阿拉伯语、重音符号和混合语言文本。产品应始终允许用户校对 OCR 结果。

### 9.10 单词本、短语本与句子本

语迹应避免只做传统单词本。更重要的是保留真实上下文。

建议分为三层：

- 单词。
- 短语。
- 整句表达。

每个收藏项应关联：

- 原始日记。
- 所属照片。
- 母语上下文。
- 目标语言上下文。
- 音频。
- 复习记录。
- 用户熟悉度。

句子本应成为高级功能之一，因为用户真正想掌握的往往不是单个词，而是“我在真实生活中会用到的整句表达”。

### 9.11 词典与用户自定义资源

语迹计划支持词义查询、例句、发音、收藏和复习。

可扩展能力：

- 用户导入自己的词典资源。
- 自定义词典优先级。
- 离线词典。
- 多语种词典。
- 例句来源标注。
- 将词典解释与用户自己的生活上下文结合。

### 9.12 长期语言记忆系统

随着使用时间增加，语迹应沉淀出用户自己的语言记忆系统。

长期记忆包括：

- 双语生活记录。
- 常用主题。
- 常用表达。
- 高频词汇。
- 反复遗忘的词。
- 已掌握的句型。
- 收藏的照片故事。
- 不同阶段的语言水平变化。
- 用户在目标语言中越来越能自然表达的生活领域。

可视化方向：

- 本月我学会表达的主题。
- 我的高频生活词汇。
- 我的常用情绪表达。
- 我最常写的场景。
- 一年前的今天，我现在能如何用目标语言重新表达。
- 我的语言成长时间线。

## 10. 向量化数据与个人语义记忆

考虑到长期记忆，语迹需要设计向量化数据记录能力。

不建议在面向普通用户的主宣传语里直接使用“向量化”这个词，但它应成为产品底层能力。用户层面可以称为：

- 个人语言记忆。
- 个人语义记忆。
- 我的生活语料库。
- 我的表达库。
- 语言成长轨迹。

### 10.1 需要向量化的内容

建议为以下内容建立向量索引：

- 母语原始记录。
- 目标语言生成文本。
- 逐句对齐后的句子对。
- 照片描述和照片写作提示。
- 用户收藏的单词、短语和句子。
- 用户手动添加的笔记。
- 听写和回译结果。
- 用户常用表达和常见错误。
- 用户直接用目标语言写下的原文。
- AI 修改后的目标语言文本。
- 手写文章 OCR 识别文本。
- 手写原图的文字摘要和关联描述。

### 10.2 向量化用途

向量化能力可以支持：

- 语义搜索：查找“我以前写过关于雨天、焦虑、旅行、咖啡馆的内容”。
- 上下文召回：AI 生成新文本时参考用户过去的表达习惯和学习水平。
- 复习推荐：发现用户经常遇到但掌握不牢的表达。
- 主题聚类：自动归纳用户常写主题。
- 语言成长分析：观察用户表达复杂度、词汇量和句型变化。
- 关联照片与文本：把照片故事、日记和学习句子串联起来。
- 个性化句库：从用户自己的记录中生成最值得复习的句子。

### 10.3 本地优先原则

向量化数据应默认保存在本地。

需要明确区分：

- 原始数据。
- AI 生成数据。
- 向量索引。
- 音频文件。
- 用户配置。
- 同步配置。

用户应能导出、备份、删除或重建本地向量索引。

如果使用远程 embedding API，应让用户明确配置并知情。默认策略应偏保守：本地数据优先，用户主动启用外部 AI 能力。

## 11. 本地优先、隐私与自定义配置

语迹的隐私设计是核心卖点之一。

基本原则：

- 数据默认存储在本地。
- 用户拥有自己的记录、词句、音频、照片和学习历史。
- AI 功能需要用户主动配置 API Key 或 AI 请求信息后才启用。
- App 应内置默认 Prompt Preset，让用户无需配置 prompt 也能使用核心功能。
- 用户应能自定义、导入和导出 Prompt Preset，以便掌控 AI 文本转换规则。
- 多端同步由用户自定义配置对象存储或其他同步方案。
- App 不应默认把用户日记、照片或学习记录上传到平台服务器。
- 用户应能导出和迁移数据。

建议宣传表达：

> 本地优先。买断使用。AI 与同步由你掌控。

英文：

> Local-first. Pay once. Bring your own AI and sync.

更正式的说明：

> 数据默认保存在本地；AI 请求和多端同步均由用户自行配置。

英文：

> Your data stays local by default. AI requests and sync are configured by you.

## 12. 商业模式

语迹计划采用买断制。

买断制与产品价值观匹配：

- 强调长期使用。
- 强调本地优先。
- 强调用户拥有数据。
- 避免用户担心日记和隐私内容被平台长期托管。
- 与“高质量、设计感强、可长期使用的工具”定位一致。

需要注意：

- 如果 App 不承担 AI 推理成本，需清楚说明用户需要自行配置 AI API Key 或请求信息。
- 如果后续提供官方托管 AI 或同步服务，可以作为可选增值服务，而不是默认依赖。
- 买断制可以先覆盖核心本地功能，高成本云服务另行收费。

可能的定价结构：

- 一次性买断：核心功能、本地数据库、基础记录、基础训练、词句库。
- 可选增值：官方同步服务、官方 AI 服务、跨设备托管备份、高级语音服务。
- 专业功能：高级导出、批量处理、词典导入、长期统计、高级向量搜索。

## 16. 产品原则

语迹后续设计和开发应遵循以下原则：

- 生活优先：用户自己的生活内容是第一素材。
- 本地优先：默认不上传用户记录和照片。
- 用户掌控：AI、同步、导出、删除都应由用户明确控制。
- 语境优先：单词和短语应尽量保留原始上下文。
- 长期优先：设计要服务几个月、几年后的积累价值。
- 简洁优先：首页不要变成复杂学习仪表盘。
- 多语种优先：不要把产品假设锁死在英语学习。
- 训练闭环优先：记录之后应自然进入听、说、写、译、复习。

## 18. 产品核心对象模型

为了避免产品变成松散功能集合，语迹应围绕一组稳定的核心对象设计。

第一版首次启动通过引导问答创建第一个语言空间，但底层应支持多个 Space。每个 Space 对应一个目标语言学习档案。所有主数据对象必须关联 `space_id`，不建议把多目标语言混在同一个 Space 中。

建议核心对象分为五层：

1. Space：某一门目标语言的学习空间，例如“英语空间”。
2. Entry：用户原始生活记录。
3. Rendering：AI 基于 Entry 生成的目标语言版本。
4. Practice：用户围绕 Rendering 进行的练习结果。
5. Memory：从 Entry、Rendering 和 Practice 中沉淀出的长期语言记忆。

### 18.1 Space

Space 表示一个目标语种学习空间。

建议字段：

- space_id。
- 名称，例如“英语空间”。
- 默认母语。
- 目标语言，例如英语。
- 默认学习水平。
- 默认 AI Provider 配置引用。
- 默认同步配置引用。
- 创建时间和更新时间。

第一版首次启动在用户输入并确认母语、目标语言、水平自评后创建第一个 Space；后续应允许用户通过“添加学习语言”创建新的语言空间。空间切换应表达为语言切换，例如“英语 / 日语 / 添加学习语言”，而不是 Project 管理。

### 18.2 Entry

Entry 是语迹的起点，代表用户记录的一段真实生活材料。

Entry 可以包含：

- 母语文本。
- 目标语言原文。
- 照片。
- 手写文章原图。
- OCR 识别文本。
- space_id。
- 输入方式：键盘输入、照片引导、手写拍照录入、导入文本。
- 时间。
- 地点。
- 情绪。
- 标签。
- 相关人物。
- 用户手动备注。
- 是否允许发送给 AI。
- 是否参与向量化索引。

Entry 的产品含义是：这是用户生活中的一段真实语境。

### 18.3 Rendering

Rendering 是 AI 将 Entry 转换成目标语言后的学习版本。

同一个 Entry 可以拥有多个 Rendering，例如：

- 自然表达版。
- 简单入门版。
- 口语版。
- 正式书面版。
- 逐句讲解版。
- 用户自定义 Prompt Preset 生成版本。

Rendering 应记录：

- 目标语言。
- 使用的 Prompt Preset。
- 使用的模型。
- 生成时间。
- 生成参数。
- 是否被用户收藏或设为首选版本。
- 用户对质量的反馈。

Rendering 的产品含义是：这是用户生活材料在目标语言中的一种表达方式。

### 18.4 Practice

Practice 是用户围绕某个 Rendering 进行的训练记录。

Practice 可以包含：

- 跟读记录。
- 听写结果。
- 回译结果。
- 目标语言写作检查结果。
- AI 修改历史。
- 复述结果。
- 朗读录音。
- 错误标记。
- 熟悉度。
- 复习历史。

Practice 的产品含义是：用户不是只看 AI 生成内容，而是在真实训练中把内容变成能力。

### 18.5 Memory

Memory 是语迹长期价值的核心。

Memory 可以来自：

- 用户主动收藏的单词、短语、句子。
- AI 自动提取的高价值表达。
- 用户反复出错的表达。
- 用户目标语言写作中的错误模式。
- AI 修改后被用户接受的句子。
- 用户高频主题。
- 用户常用语境。
- 用户照片和日记形成的语义关联。

Memory 的产品含义是：语迹用得越久，越了解用户自己的语言生活。

## 19. 学习意图与生成参数

用户不应直接被 prompt 工程概念打扰。Prompt Preset 是底层机制，产品层应提供更容易理解的“学习意图”入口。

用户创建或转换一条记录时，可以选择本次学习意图：

- 我想学日常口语。
- 我想学更地道表达。
- 我想练听力。
- 我想练写作。
- 我想检查我自己写的目标语言。
- 我想练跟读。
- 我想准备旅行。
- 我想用于工作场景。
- 我想表达情绪。
- 我想整理照片故事。

学习意图可以映射到默认 Prompt Preset、输出格式、解释深度和练习方式。

### 19.1 难度控制

AI 生成内容必须支持学习难度控制，否则容易出现“内容正确但用户学不动”的问题。

建议参数：

- CEFR 等级：A1、A2、B1、B2、C1、C2。
- 句子长度：短句、自然、稍复杂。
- 词汇难度：基础、常用、进阶。
- 表达风格：直译辅助、自然表达、地道表达。
- 输出密度：只给结果、逐句解释、深度讲解。
- 语速建议：慢速、正常、自然口语。

这些参数可以由用户显式选择，也可以根据用户长期学习记录自动推荐。

### 19.2 生成结果的多版本策略

同一条 Entry 可生成多个 Rendering，但界面上应避免复杂。

建议默认只显示一个主版本，并提供：

- 换一种说法。
- 变简单一点。
- 更地道一点。
- 更口语一点。
- 加入逐句讲解。
- 生成适合跟读的版本。

这比让用户面对一长串模式列表更自然。

## 20. AI 生成质量、可信度与纠错机制

语迹生成的是学习材料，因此 AI 输出必须可追溯、可修正、可替换。

建议支持：

- 重新生成。
- 生成更保守版本。
- 生成更地道版本。
- 查看为什么这样表达。
- 对比多个生成版本。
- 用户手动编辑目标语言文本。
- 标记“不自然”。
- 标记“太难”。
- 标记“不符合原意”。
- 保存用户认可版本。

每个 AI 生成结果应保留基础元数据：

- 原始 Entry。
- Prompt Preset。
- 模型。
- 生成时间。
- 目标语言。
- 学习等级。
- 是否引用长期记忆。

长期记忆系统应优先使用用户认可、收藏或练习过的内容，而不是无差别吸收所有 AI 输出。

## 21. 长期记忆的三层结构

语迹的长期记忆应分为三类，而不是只理解为向量数据库。

### 21.1 内容记忆

内容记忆回答：

> 我过去记录过什么？

它包含：

- 日记。
- 照片。
- 时间线。
- 地点。
- 情绪。
- 主题。
- 生活片段。

向量化搜索主要服务内容记忆。

### 21.2 语言记忆

语言记忆回答：

> 我学过哪些语言表达？

它包含：

- 单词。
- 短语。
- 整句表达。
- 常用句型。
- 原始上下文。
- 音频。
- 复习记录。

间隔重复和词句复习主要服务语言记忆。

### 21.3 学习记忆

学习记忆回答：

> 我哪里反复出错，哪些表达还没有真正掌握？

它包含：

- 听写错误。
- 回译偏差。
- 跟读问题。
- 高频遗忘词。
- 反复混淆表达。
- 用户已掌握主题。
- 用户正在突破的表达能力。

学习记忆可以反过来影响 Prompt Preset、复习推荐和首页练习建议。

## 22. 隐私感知与 AI 请求透明度

语迹的隐私优势不应只停留在文案层面，而应体现在具体交互中。

建议设计：

- 每条 Entry 可设置是否允许发送给 AI。
- 每条 Entry 可设置是否参与向量索引。
- AI 请求前可预览将发送的文本、图片摘要和上下文。
- 支持对人名、地点、公司名、联系方式做本地脱敏。
- 显示每条记录是否已调用外部 AI。
- 显示每条记录是否已生成本地向量索引。
- 用户可删除某条记录的 AI 生成结果。
- 用户可删除或重建本地向量索引。
- 用户可导出完整数据。
- 用户可查看本地数据存储位置。

AI、Embedding、TTS 和同步应视为不同能力，分别配置，分别授权。

## 23. 自定义 AI Provider 与模型配置

语迹的高级用户可能希望接入不同 AI 服务，因此 AI 配置应设计成 provider 体系，而不是单一 API Key 输入框。

建议支持：

- OpenAI-compatible endpoint。
- Chat model 配置。
- Embedding model 配置。
- TTS provider 配置。
- API Key 本地钥匙串保存。
- 请求模板。
- 连接测试。
- token 或费用预估。
- 每个 Prompt Preset 指定模型。
- 低成本模式。
- 高质量模式。
- 离线或本地模型的未来扩展。

产品上应区分：

- 普通用户：只看到“启用 AI 功能”和最少配置。
- 高级用户：可以配置 provider、模型、preset 和请求格式。
- 专家用户：可以调试 prompt、查看请求预览和导入导出配置。

## 24. 同步、加密与冲突处理原则

用户自定义对象存储是语迹的重要高级卖点，但同步方案必须提前定义边界。

需要考虑：

- 是否端到端加密。
- 多设备同时编辑如何处理。
- 照片是否同步。
- 音频是否同步。
- AI 生成内容是否同步。
- 向量索引是否同步。
- Prompt Preset 是否同步。
- AI Provider 配置是否同步。
- API Key 是否永不同步。

建议原则：

- 原始记录、用户编辑内容、收藏词句、Prompt Preset 可以同步。
- 照片和音频可由用户选择是否同步。
- 向量索引默认不跨设备同步，而是在每台设备本地重建。
- API Key 默认只保存在本机钥匙串，不参与对象存储同步。
- 冲突处理优先保留多个版本，而不是自动覆盖。

可考虑支持的同步目标：

- S3。
- Cloudflare R2。
- MinIO。
- WebDAV。
- iCloud Drive。
- 本地文件夹。

第一版不必全部实现，但文档和数据模型应预留空间。

## 25. 首页信息架构与核心用户路径

语迹的首页应避免复杂仪表盘。第一屏应围绕用户最核心的三个动作。

建议首页入口：

1. 记录：今天记录一点生活。
2. 练习：继续练最近生成的内容。
3. 记忆：搜索和回顾我的语言记忆。

### 25.1 新用户路径

新用户第一次使用时，应尽快完成一个完整闭环：

1. 选择母语。
2. 选择目标语言。
3. 完成水平自评。
4. 确认并创建第一个语言空间，例如“英语空间”。
5. 写一句今天的生活。
6. 选择学习意图。
7. 生成目标语言。
8. 听一句。
9. 跟读一句。
10. 收藏一个表达。

第一次体验不应要求用户先配置复杂同步、选择数据目录、配置词典、构建向量索引或理解 Prompt Preset。

如果用户已经有目标语言写作基础，也可以走另一条轻量路径：

1. 选择目标语言写作检查。
2. 输入一小段目标语言文本。
3. 查看 AI 修改和逐句讲解。
4. 接受一个修改后的句子。
5. 将错误模式或高价值表达加入记忆。

### 25.2 老用户路径

老用户打开 App 时，应看到：

- 今天继续记录。
- 最近未练习的记录。
- 最近待修改的目标语言写作。
- 今天建议复习的词句。
- 最近常写主题。
- 可以直接搜索自己的语言记忆。

核心体验应让用户感觉：语迹记得我的生活，也记得我的语言成长。

## 26. 与同类产品的差异化矩阵

语迹应避免进入拥挤的“AI 语言老师”赛道，而应明确站在“个人生活语料库驱动的语言学习工具”位置。

| 产品类型 | 代表产品 | 核心优势 | 语迹的差异点 |
|---|---|---|---|
| 游戏化课程 | Duolingo | 轻量、关卡、习惯养成、AI Roleplay | 语迹不以课程为中心，而以用户自己的生活内容为中心 |
| 结构化课程 | Babbel / Busuu | 课程体系、复习、AI 对话、口语练习 | 语迹不是按课程推进，而是把每天的生活变成学习材料 |
| 发音训练 | ELSA Speak | 英语发音评分、语音反馈、口音训练 | 语迹覆盖多语种和完整语境，不只做发音纠错 |
| 外部内容阅读 | LingQ / Readlang | 导入文章、点词翻译、上下文词汇 | 语迹的材料来自用户自己的日记、照片和想法 |
| 字幕学习 | Language Reactor | YouTube / Netflix 双字幕、视频输入 | 语迹不是观看外部内容，而是生成个人生活语料 |
| 卡片复习 | Anki / Mochi | 间隔重复、长期记忆、卡片自由度 | 语迹的复习回到生活上下文，而不是孤立卡片 |
| 写作纠错社区 | Journaly / LangCorrect | 写目标语言文章，获得社区反馈 | 语迹允许先用母语记录，再由 AI 生成可学习的目标语言版本 |
| AI 对话陪练 | Talkpal / Praktika / Memrise AI | AI tutor、roleplay、实时对话 | 语迹不是聊天机器人，而是长期个人语言记忆系统 |

对于 Journaly / LangCorrect 这类写作产品，语迹也应覆盖“用户直接用目标语言写作并获得修改”的场景。但语迹的重点不是社区纠错或泛作文批改，而是把目标语言写作、AI 修改、错误模式和生活记录一起沉淀进个人语言记忆。

语迹的四个核心差异应持续强化：

- 我的生活内容，而不是平台课程。
- 我的语言记忆，而不是一次性翻译。
- 我的本地数据，而不是云端锁定。
- 我的 AI 配置，而不是平台黑盒。

最终产品表达应避免说成“AI 帮你翻译日记”。更准确的表达是：

> 语迹把你的生活持续构建成一个可听、可说、可复习、可搜索的个人语言记忆系统。
