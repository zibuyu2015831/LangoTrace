导航栏三元素协调性 · 修订方向

你保留了居中标题，当前不协调的根因有三：① 主次压反——胶囊带边框 + 阴影 + 地球图标，是视觉最重的元素，却只承载次要的语言上下文，而页面身份「记录」只是一行最轻的裸文字；② 形与重不统一——38pt 药丸胶囊 / 44pt 圆形描边齿轮 / 无容器标题，三种视觉语汇各说各话；③ 居中被带偏——胶囊偏宽把标题挤向左，右侧空出一段。下面三个方向都保留标题、只统一三元素关系（触控目标仍 ≥44pt，视觉尺寸为示意）。

A · 降权胶囊轻重对比 · 标题为锚

胶囊去地球图标 / 去阴影、收为安静 chip，齿轮转透明无描边；标题加重为唯一锚点。靠「轻重对比」把次要语境压到后景。
B · 统一描边控件（推荐）对称双控件 · 标题居中
9:41
记录
胶囊与齿轮统一为「同高 + 同 hairline 描边 + 无阴影」同一控件家族，成对称双控件夹住居中标题。靠「控件配对」建立秩序，最稳。

第二轮 · 双边框克制化与左右平衡

第二轮反馈：方向 B 的「胶囊描边 + 齿轮描边」双容器，叠在下方 Hero 卡 / 写一句 / 用照片开始 / 筛选 chip / 空状态卡一连串描边之上，顶部显得繁杂，不够克制；且宽胶囊与小齿轮左右失衡。关键事实：spec/002 §54 / §157 规定顶部轻量上下文就是 英语 · B1（目标语言 + 等级），并非「中文 -> 英语 · B1」——当前实现其实多显示了母语侧。下面三个方向都去掉导航栏描边回到克制，差异在「语言上下文保留多少 / 左右如何平衡」（触控目标仍 ≥44pt）。

9:41

只保留语言一个软底胶囊（无描边、无阴影），齿轮转裸图标。语言作为产品核心上下文用一处低对比 fill 微微凸显，齿轮退为次要图标——既消掉双描边，又保留语言的可点存在感；左右仍不等宽，但只剩一个容器，繁杂感大幅下降。

语言标签文案 · 自然语言 vs 语种代码

第三轮提问：用 cn / en 这类代码如何？关键事实：cn 是国家代码（ISO 3166），中文的语种代码是 zh（ISO 639）；cn → en 把国家码与语种码混用，技术上不一致。代码更紧凑，但偏技术气质、与产品暖调冲突，且对中文用户「英语」并不比「EN」长多少却更易读（spec/002 §54 也规定为「英语 · B1」）。下面并排对比文案形态：

英语 · B1 目标语 + 等级（推荐） spec §54 写法；中文秒读、暖、含等级
中 → 英 · B1 中文单字 + 方向 紧凑、暖、正确、有方向感；次选
EN · B1 目标语种码 + 等级 紧凑，但大写码偏技术感、丢暖度
ZH → EN 语种码（正确写法） zh 才是中文语种码；多数用户不认识 zh
CN → EN 国家码（你的写法 · 不准确） cn 是国家码不是语种码，与 en 语种码混用不一致

评审结论与修订

  • 同根问题：胶囊 + 齿轮在滚动正文 → SwiftUI 导航栏 inline 区全空 = 顶部留白；齿轮逐页手搓 → 阅读页缺齿轮。方向 B 把二者上移进共享导航栏一并解决。
  • 细节执行修订（评审 5 → 8）：导航栏到首个内容保留 20pt 呼吸（回收大标题带，但不抹掉所有空间）；去掉导航栏底部 hairline，避免与 Hero 卡顶部边框两条横线打架。
  • 保留 inline 标题：导航栏中央保留「记录 / 阅读 / 练习 / 记忆」，既给页面身份，又给 push 详情页的返回标签；标题绝对居中、加重为锚点（weight 700），不被左侧胶囊带偏。
  • 三元素协调（采纳方向 B · 统一描边控件）：语言胶囊与设置齿轮统一为同一描边控件家族——同高、同 1px hairline、无阴影、同 pill 圆角，成对称双控件夹住居中标题；去掉胶囊的地球图标（「中文 → 英语」已表达语言含义，图标冗余）并压缩胶囊宽度，让标题真正居中。解决原先「主次压反 / 形与重不统一 / 居中被带偏」三处不协调。备选 A（降权胶囊）会让胶囊过淡、削弱语言切换入口可发现性；C（accent 绿文字入口）占用 accent 绿，违反「accent 只表示可操作 / 主动作」语义，均不采纳。
  • 一致性：四 tab（含阅读）共用同一套导航栏修饰符，结构上不可能再漏齿轮；设置详情页用 showsContextHeader: false 门控，不注入胶囊/齿轮。
  • 最终采纳（第二/三轮 → 方向 A · 去边框 + 紧凑目标语）：双描边过繁杂、不够克制，且左右失衡。最终改为两侧均去描边（描边语汇留给内容卡），语言显示 spec/002 §54 / §157 的 英语 · B1（目标语 + 等级）+ 下拉指示，齿轮为裸图标；左右平衡靠「同样低对比」而非等宽。否决语种代码：cn 是国家码（语种码应为 zh）、混用不一致，且代码冷感与产品暖调 / spec 冲突。完整 中文 -> 英语 · B1 仅作 VoiceOver value。
  • 权威边界：本原型是设计基准与评审证据，不是实现事实源；落地以 active plan 与 spec/002 §54-55、spec/003 §143 为准。
