# 记录页头部优化评审原型

本目录是 iPhone 四 tab 头部重构（语言胶囊 + 设置齿轮上移进导航栏）的设计评审原型与证据，对应任务方案
`docs/plans/active/2026-06-20-refactor-phone-root-context-toolbar.md`。

## 打开方式

直接打开 `index.html`，无需本地服务器，复用 `../../shared/tokens.css` 与 `../../shared/components.css`，
不依赖 npm / 框架 / CDN / 远程资源（与 `prototypes/README.md` 约束一致）。

## 评审结论

两个问题同一根因：语言胶囊与设置齿轮被放进滚动正文（`PhoneContextHeader`），对应 SwiftUI 即
`.navigationTitle` 大标题导航栏的 inline 区全空 → 顶部留白；齿轮按 `onSettingsAction` 逐页手搓 → 阅读页缺失。
方向 B 把胶囊 + 齿轮上移进导航栏 `.inline` 上下文条，四 tab（含阅读）共用。

5 维度评审（App UI，最重功能性 / 细节执行）：总评 6.6 → 修订后约 8.0。

- 功能性 7 / 视觉层级 7 / 哲学一致性 8 / 创新性 6。
- 细节执行 5 → 8（本轮修订项）：
  1. 顶部保留 **20pt 呼吸**——回收大标题带，但不让内容贴住导航栏（用户反馈「压迫感」的直接修复）。
  2. 去掉导航栏底部 hairline，避免与 Hero 卡顶部边框两条横线打架。
  3. 保留导航栏居中 inline 标题（记录 / 阅读 / 练习 / 记忆）给页面身份与 push 详情页返回标签；
     标题绝对居中、加重为锚点，语言胶囊去前导图标 + 压缩宽度，避免与标题挤压。

## 三元素协调修订（采纳方向 B）

第二轮用户指出「语言胶囊 + 标题 + 齿轮」三元素不协调，根因三处：① 主次压反（胶囊视觉最重却只承载次要语境）；
② 形与重不统一（药丸胶囊 / 圆形描边齿轮 / 无容器标题三种语汇）；③ 居中被宽胶囊带偏。
渲染三方向对比后采纳 **方向 B · 统一描边控件**：胶囊与齿轮统一为同一描边控件家族（同高、同 1px hairline、
无阴影、同 pill 圆角），对称夹住居中标题；去掉胶囊地球图标、压缩宽度，标题加重为锚点（见本页底部
「导航栏三元素协调性」对比区）。备选 A（降权胶囊）会让胶囊过淡、削弱语言切换入口可发现性；
C（accent 绿文字入口）占用 accent 绿，违反「accent 只表示可操作 / 主动作」语义——均不采纳。

## 第二/三轮：去边框 + 紧凑文案（采纳方向 A）

第二轮反馈：方向 B 的「胶囊描边 + 齿轮描边」双容器叠在下方一连串卡片描边上显得繁杂、不够克制，且宽胶囊与小齿轮左右失衡。第三轮提问：可否用语种代码（cn/en）。
评审结论（见本页底部「双边框克制化」与「语言标签文案」两节）：

- **采纳方向 A · 去边框**：语言 chip 与齿轮均去描边 / 填充（裸控件），平衡靠「同样低对比」而非等宽。
- **否决语种代码**：`cn` 是国家码（ISO 3166），中文语种码是 `zh`（ISO 639），`cn → en` 混用不一致；`zh` 对普通用户陌生；代码偏技术冷感、与产品暖调及 spec §54 冲突。若要紧凑 + 方向感，`中 → 英 · B1` 比代码更优（可读、暖、正确）。

## 第四轮：顶部语言收敛为仅目标语言（最终采纳 V3）

实机浅色截图后，用户提出「只保留语种『英语』、去掉 B1、文本居中、加描边收成小 tag」以求左右更协调。
评审结论（见本页底部「第四轮 · 只保留语种 + 紧凑对称」三方向对比）：

- **采纳 V3 · 去 B1 但不加描边**：缩短为 `英语` 后左侧体量自然靠近齿轮，协调感无需描边即可达成，延续第二轮「零描边最克制」共识；语言显示收敛为目标语言 `英语`，完整 `中文 -> 英语 · B1` 仍仅作 VoiceOver value。
- **否决加描边**：V1（chip 描边 + 齿轮裸露）语汇不一致（回到第一轮「形与重不统一」）；V2（两边都描边）虽对称但重现双描边，正是第二轮要避开的方向。
- **去 B1 的依据**：spec/002 §54 / §157 写的是「**例如** `英语 · B1`」（举例非强制）；一门空间只对应一门语言（核心决策 #4），目标语言已唯一标识当前空间，等级是少变水平自评。
